# ReadPicoPush APK 使用说明（傻瓜版）

> 适用：荣耀 / Android 16 / 无 Google Play 的手机。不用装任何第三方自动化软件，
> 不用 root。安装包就是 `ReadPicoPush.apk`（25 KB，debug 签名，侧载即用）。

## 一、安装（1 分钟）

1. 把 `ReadPicoPush.apk` 传到手机（数据线 / 微信文件传输 / 网盘都行）。
2. 点开这个文件。系统可能提示「未知来源应用」——**允许**即可安装
   （设置路径各机型略有不同：一般是弹窗里点「设置」→ 打开「允许此来源」→ 返回）。
3. 安装完桌面出现图标：**PicoPush 推送**。

## 二、首次使用（授权两步）

1. 打开 App。**启动时自动读取剪贴板**——你先复制一段文字再开 App，文字就已在输入框里。
   （没自动填？点「读取剪贴板」按钮。）
2. 点「发送到墨水屏」。第一次会弹**蓝牙权限**请求（附近设备 / 蓝牙连接）：
   **都选「允许」**。拒绝的话推送不了，可以在系统设置 → 应用 → PicoPush 推送 → 权限里补。

> App 只用蓝牙，不联网、不读位置（Android 12+ 的蓝牙扫描权限带
> `neverForLocation` 标记，系统不会给它定位能力）。

## 三、推送（每次就三步）

1. **在墨水屏上**：进「接收推送」，让设备发出 `PicoPush-XXXX` 广播（武装窗口期）。
2. **在手机上**：复制或输入要推的文字（输入框已自动带剪贴板内容）。
3. 点「**发送到墨水屏**」。日志区会依次显示：

```
扫描 PicoPush-XXXX 广播（最多 12 秒）……
发现 PicoPush-1A2B（token=0x1A2B）
连接中……
已连接，协商 MTU……
MTU=247，每包 241 字节
订阅设备通知（5f13）……
发送 BEGIN（83 字节，标题「……」）……
设备就绪（session=1），正文 1234 字节，开始传输……
数据发送完毕（6 包），发送 END 等待设备校验……
推送完成：设备已校验 CRC32 并开书 ✓
```

看到最后一行 + 手机弹出「推送完成 ✓」= 成功，墨水屏会自动亮屏开书。

## 四、单词卡模式

勾选「**单词卡模式**」再点发送：正文忽略，输入框里的词作为单词卡 title，
设备弹内置词典卡片，不开整书。

## 五、排错表

| 现象 | 原因 | 处理 |
|------|------|------|
| 日志「12 秒内未发现 PicoPush-XXXX 广播」 | 设备没开接收 / 不在窗口期 / 蓝牙没开 | 先在墨水屏开「接收推送」；确认手机蓝牙已开 |
| 日志「设备拒绝：设备未处于接收窗口」 | 广播过期，武装窗口已关 | 回设备重新开「接收推送」，再点一次发送 |
| 日志「设备拒绝：CRC32 校验不符」 | 传输被干扰（极少见） | 直接再点一次发送（重开会话） |
| 日志「设备未接受写入」 | 蓝牙链路异常 | 离设备近一点，重试 |
| 日志「等待设备回应超时」 | 设备侧卡住 / 深度睡眠 | 看设备屏幕是否活着；重试 |
| 日志「权限被拒绝」 | 蓝牙权限没给 | 系统设置 → 应用 → PicoPush 推送 → 权限，全开 |
| 完全没有日志反应 | 权限弹窗还在等 | 看屏幕上方有没有权限对话框 |

## 六、技术备注（给想看原理的人）

- 协议与固件 `components/push_sink` 逐字段对表：BEGIN(83B) 写特征 5f12 →
  等 READY → DATA 帧（seq u16 小端 + len + ≤241B 载荷）逐包写 5f11，
  **写请求（WWR）逐包等 ATT 回执** → END 写 5f12 → 等 DONE(0x12)/ERR(0x13)。
- 每包 241 字节 = MTU 247 − 3(ATT 写头) − 3(帧头)；MTU 协商失败时自动退到
  每包 17 字节（慢但能推）。
- 断点续传是设备侧能力：中断后重连，设备会告知从哪续——本 App 暂未实现
  RESUME 快进（M1 交付范围外），失败重推即可，数据不会错。
- 源码在仓库 `tools/android/apk/`（`build-apk.sh` 一键重建，协议层有 25 条
  宿主机对表断言）。
