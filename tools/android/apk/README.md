# ReadPicoPush APK 使用说明（傻瓜版）

> 适用：荣耀 / Android 16 / 无 Google Play 的手机。不用装任何第三方自动化软件，
> 不用 root。安装包就是 `ReadPicoPush.apk`（41 KB，debug 签名，侧载即用）。

## 一、安装（1 分钟）

1. 把 `ReadPicoPush.apk` 传到手机（数据线 / 微信文件传输 / 网盘都行）。
2. 点开这个文件。系统可能提示「未知来源应用」——**允许**即可安装
   （设置路径各机型略有不同：一般是弹窗里点「设置」→ 打开「允许此来源」→ 返回）。
3. 安装完桌面出现图标：**PicoPush 推送**。

## 二、首次使用（授权两步）

1. 打开 App。**启动时自动读取剪贴板**——你先复制一段文字再开 App，文字就已在输入框里。
   （没自动填？点「读取剪贴板」按钮。）
2. 点「发送到墨水屏」。第一次会弹**蓝牙权限**请求（附近设备 / 蓝牙连接）：
   **都选「允许」**。拒绝的话推送不了，可以在系统设置 → 应用 → PicoPush 推送 → 权限里补。

> App 只用蓝牙，不联网、不读位置（Android 12+ 的蓝牙扫描权限带
> `neverForLocation` 标记，系统不会给它定位能力）。

> ## ⚠️ 首次使用请务必先手动打开一次 App
>
> **装完后请先正常打开一次 App 并完成上面的授权**，之后才可以用桌面快捷方式
> 「一键推流」。原因：快捷方式不会弹蓝牙权限框——
> 如果你从没打开过 App 授权，快捷方式会提示「请先打开 PicoPush 一次并授予蓝牙权限」
> 然后结束。授权一次后就永久可用。

## 四、桌面快捷方式「一键推流」（极简弹窗版）

长按桌面「PicoPush 推送」图标 → 点「一键推流」，或把它**拖到桌面当独立图标**。

点它会弹出一个**很小的窗口**：

1. 窗口里直接显示 **「已读取剪贴板（N 个字符）」**和开头一小段预览；
2. 你点 **「发送」** → 立刻扫描连接并推送，完成后窗口自动关闭；
3. 不想发就点「取消」。

> **为什么要多这一步？（真机实测教训）**
> 最早做成"完全无界面、静默读剪贴板直接推"，结果被系统隐私权限拦下：
> 弹「允许读取剪贴板」、选「仅使用期间允许」后**仍然读不到**——
> 系统（尤其荣耀 / Android 16 这类国产 ROM）不允许无界面的透明窗口在后台读剪贴板。
> 所以改成**可见小弹窗 + 你亲手点一下「发送」**：有了前台交互，系统必然放行。
> 而且剪贴板是在**你点「发送」的那一刻**读取的（用户手势内），这是最稳的时机。

## 三、推送（每次就三步）

1. **在墨水屏上**：进「接收推送」，让设备发出 `PicoPush-XXXX` 广播（武装窗口期）。
2. **在手机上**：复制或输入要推的文字（输入框已自动带剪贴板内容）。
3. 点「**发送到墨水屏**」。日志区会依次显示：

```
扫描 PicoPush-XXXX 广播（最多 12 秒）……
发现 PicoPush-1A2B（token=0x1A2B）
连接中……
已连接，协商 MTU……
MTU=247，每包 241 字节
订阅设备通知（5f13）……
发送 BEGIN（83 字节，标题「……」）……
设备就绪（session=1），正文 1234 字节，开始传输……
数据发送完毕（6 包），发送 END 等待设备校验……
推送完成：设备已校验 CRC32 并开书 ✓
```

看到最后一行 + 手机弹出「推送完成 ✓」= 成功，墨水屏会自动亮屏开书。

## 四、单词卡模式

勾选「**单词卡模式**」再点发送：正文忽略，输入框里的词作为单词卡 title，
设备弹内置词典卡片，不开整书。

## 五、排错表

| 现象 | 原因 | 处理 |
|------|------|------|
| 日志「12 秒内未发现 PicoPush-XXXX 广播」 | 设备没开接收 / 不在窗口期 / 蓝牙没开 | 先在墨水屏开「接收推送」；确认手机蓝牙已开 |
| 日志「设备拒绝：设备未处于接收窗口」 | 广播过期，武装窗口已关 | 回设备重新开「接收推送」，再点一次发送 |
| 日志「设备拒绝：CRC32 校验不符」 | 传输被干扰（极少见） | 直接再点一次发送（重开会话） |
| 日志「设备未接受写入」 | 蓝牙链路异常 | 离设备近一点，重试 |
| 日志「等待设备回应超时」 | 设备侧卡住 / 深度睡眠 | 看设备屏幕是否活着；重试 |
| 日志「MTU 协商失败（23），本次无法发送，请重试」 | gen14 起新增：MTU 没谈到 247 时明确失败，不再闷头走低速长写 | 离设备近一点，重试一次（多半能谈成） |
| 日志「设备要求从 N 字节续传」 | 设备有上一次推送的半成品簿记 | 重新完整发送一次即可 |
| 日志「权限被拒绝」 | 蓝牙权限没给 | 系统设置 → 应用 → PicoPush 推送 → 权限，全开 |
| 完全没有日志反应 | 权限弹窗还在等 | 看屏幕上方有没有权限对话框 |

## 六、技术备注（给想看原理的人）

- 协议与固件 `components/push_sink` 逐字段对表：BEGIN(83B) 写特征 5f12 →
  等 READY → DATA 帧（seq u16 小端 + len + ≤241B 载荷）逐包写 5f11，
  **写请求（WWR）逐包等 ATT 回执** → END 写 5f12 → 等 DONE(0x12)/ERR(0x13)。
- 每包 241 字节 = MTU 247 − 3(ATT 写头) − 3(帧头)；MTU 协商失败时
  **gen14 起明确报错重试**（不再静默走每包 17 字节的长写路径）。
- 断点续传：设备侧有能力（中断后重连会答 RESUME 帧）。gen14 起 App 能识别
  RESUME：offset 为 0 时从头重发；非 0 时提示「重新完整发送」。失败重推即可，
  数据不会错。
- 源码在仓库 `tools/android/apk/`（`build-apk.sh` 一键重建，协议层有 25 条
  宿主机对表断言）。

## 七、AI 查词（v1.2 起，需 Android 8+ 与联网）

墨水屏上点英文词 → 手机算释义 → 释义自动回传到设备并弹出卡片。**AI 是手机上
跑的**：API key、模型、提示词都在 App 里，改起来不用动固件。

**v1.3 起，AI 只补位词典未收的词**：本地词典命中的词直接出词典卡（一词一答），
只有词典查不到的词才请 AI——不重复出卡、不白烧额度。

### 怎么用（三步）

1. 点 **「AI 设置」**：填 API key（默认服务商 DeepSeek，`base_url` 与 `model`
   已预填，可改成任何 OpenAI 兼容接口）。**key 只存本机，不进代码仓库。**
2. 点 **「连接并监听点词」**：App 连上墨水屏后**保持连接**（推送流程是推完即断，
   监听是另一条独立路径），状态行显示「监听中」。
3. 在墨水屏上点一个英文词：日志出现「墨水屏点词 xxx，查询中……」，约 **2–5 秒**
   后设备弹出释义卡。

> 不用时点「停止监听」即可断开。不开监听时，本 App 与旧版行为完全一致。

### v1.3：监听与推送终于可以同时进行（M1.1）

- **推送前自动停监听**：在监听中直接点「发送」，App 会先干净断开监听
  （按钮回到「连接并监听点词」），再走推送流程——不再出现「推送把监听拆了、
  界面却还显示监听中」的假状态。
- **推完自动恢复监听**：推送完成（或失败）后自动重新扫描连接订阅，日志显示
  「推送结束，正在恢复监听……」。恢复失败会如实写明原因（如「未发现设备」），
  手动再点一次「连接并监听点词」即可——不会无限重试。
- 设备侧配套（固件 gen26.3）：监听态下打开书库里的 `push.txt` 不再被弹回传书页。

### v1.4：提示词可自定义 + 模板库（M1.2）

- **提示模板可编辑**：在「AI 设置」里直接改发送给模型的提示词，可用 `{word}`
  占位符代表被点的单词（如 `解释一下 {word} 的语气和搭配`）。
- **分层铁律（永远生效）**：你改的只是 *user 角色* 的内容/风格；**系统指令
  （40 字硬约束 + 纯文本）恒定钉在 *system 角色*、永远最后追加、不可被模板覆盖**
  ——模板再怎么写也改不了输出形态，最长 169 字节帧帽兜底照旧。
- **「恢复默认」一键回到** `word: {word}`。
- **模板库（多套一键切换）**：点「AI 设置 → 管理模板库」可新建 / 编辑 / 删除 /
  一键切换多套命名模板；支持把整套模板**导出为 JSON 文件**、从文件**导入**、
  以及把单条模板**分享**为文本。导出/导入用系统文件选择器（SAF），不申请
  存储权限。

### v1.4.1：模板库三处状态同步修复（M1.2.1）

- **「切换为当前」不再擦除**：切换后设置页编辑框立即回填为新激活模板的内容
  （旧版只改激活名、编辑框留旧内容，一保存就把旧内容覆盖到新模板）。
- **「删除」真正生效**：改按模板名移除（旧版跨快照按对象身份删除，静默无效）。
- **「恢复默认」立即落库**：点完即写入并回填编辑框，不再需要再点一次「保存」。

### v1.4.2：导入重名去重

- 导入 JSON 文件内**同名模板只保留后出现的一条**，与保存路径的 upsert 语义一致
  （按名删除依赖「模板名唯一」，文件内重名会让一次删除连删多条）。

### 排错

| 现象 | 原因 / 处理 |
|---|---|
| 提示「请先点『AI 设置』填写 API key」 | 还没填 key |
| 「释义失败：HTTP 401」 | key 错了或没充值 |
| 「释义失败：请求超时」 | 网络不通 / 服务商慢，15 秒超时 |
| 点词后日志没有任何反应 | 没在监听、或设备未上报 AI 能力（状态行会写「设备不支持」） |
| 中文词没反应 | **设计如此**：AI 只服务英文词，与本地词典（英汉）一致 |

### 技术备注

- 帧：`STATUS 0x17`（设备→手机，66B，含词）→ 手机调 LLM → `CTRL 0x07`
  （手机→设备，241B：词 64B + 释义 ≤169B）回传。
- 释义上限 169 字节 = 设备侧 `PUSH_AI_DEF_MAX(170)` 留 1 字节 NUL；超长按
  **字符边界**截断（不会切出半个汉字）并加「…」。
- 服务商不锁死：`base_url` + `model` + `key` 可配，换供应商零代码改动。
- 失败**不回帧**——宁可不出卡，也不弹空卡。
