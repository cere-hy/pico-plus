读到哪一页，
旁边就聊到哪一页。

翻到新的一页，屏幕右栏会给出这一页的伴读文字：可以是翻译与主旨、一段神评论、几条干货，或把难懂的概念用大白话讲明白。听书是听书，摘要是摘要，两件事互不干扰。

开始之前 · 三件前提

① 设备刷到 26.11.30；② 手机装 v1.6.6 并点「连接并监听点词」保持连接；③ 在「AI 释义设置」填入你自己的 API key（默认 DeepSeek）。

01 / FOUR MODES

四种解读风格，随书切换

模式由设备侧选择，传给手机 App；App 按对应提示词调用模型，把当前页文本生成右栏摘要。四种风格是四套不同的角色设定，不是同一段话换个说法。

MODE 00外文原著 · 默认

毒舌双语译者

先翻译，再一句话点题

「不要逐字死译，要保留原作者的语气和情绪。直接给出翻译和总结，禁止废话。」

把这段外文翻成流畅地道的中文，再用最精炼、最接地气的一句话概括核心主旨。适合读外文小说、原文材料。

MODE 01小说 · 评论

幽默书评人

一段接地气的神评论或吐槽

「语言犀利、有趣，像朋友聊天一样，一针见血，能让人会心一笑。不要剧透后文，只评当前。」

可以结合现代生活与网络热梗解读剧情或人物心理，只评当前页，不剧透后文。适合消遣阅读。

MODE 02论述 · 干货

逻辑专栏主笔

提取论点与方法论，分点给出

「不要复述原文，请用大白话重新解构，总结出对读者最有用的 1 到 2 个干货观点。」

从当前页提取最核心的论点或方法论，用大白话重新解构、排版分点，让人一秒看懂。适合非虚构、论述类文本。

MODE 03专业 · 科普

擅长打比方的讲书高手

用生活例子讲给中学生听

「用生活中常见的例子（比如买菜、开车、建房子等）给中学生讲明白。禁止使用任何晦涩的学术名词。」

遇到复杂专业概念，改用大白话＋常见例子讲明白，通俗易懂、生动形象。适合教材、专业书。

四种风格均要求纯文本输出、不使用 Markdown 星号或加粗，摘要保留硬换行；越界的模式号会退回 MODE 00（外语原著）。
02 / HOW IT WORKS

翻一页，摘要跟着换一页

右栏约三成宽度用于伴读文字，正文仍占七成。摘要与页号严格对账，不会把上一页的文字留到这一页。

STEP 01

翻页即清空

翻到新的一页时，右栏先清掉上一页的摘要并显示「摘要生成中…」，随后再显示本页结果。旧摘要不会残留，也不会张冠李戴。

页号对账 · 正文指纹 · 回执快照
STEP 02

模型生成摘要

手机 App 收到当前页纯文本，按你选的模式调用模型。生成结果按码点裁到 250 字以内，正常输出约 180～220 字。

纯文本 · 无 Markdown · 保留硬换行
STEP 03

分帧推送、设备拼装

单帧装不下时分成 3～4 帧推送，设备侧收齐后拼装成完整摘要，上限 1024 字节。不会截断半句，也不会只显示第一帧。

250 字 · 4 帧 · 1024 B 拼装帽
关于「摘要生成中…」：设备侧不会自动降级。若模型未回帧（如网络不可用、API key 未配置或额度不足），右栏会停在占位态，或按 App 返回切到「本次未生成」；它不会编一段占位文字冒充摘要。检查手机 App 是否在线、是否已填 API key 即可定位。
03 / LAYOUT & TYPE

长摘要不挤成一条线

250 字的右栏摘要按多行文本块排版，字号自适应但设有下限，宁可截断也不缩到看不清。

01
多行文本块右栏使用自动换行的文本块，按可用宽度逐行排布；不再把整段文字塞进单行再整体缩放，避免挤成一条线。
02
字号下限 22 px字号从大到小逐档下探，取第一个能完整放下的字号；连 22 px 都放不下就停在 22 px 并补省略号，不无限缩小。
03
清晰字体渲染右栏复用设备里已验证的清晰字体链与灰阶渲染，不使用发糊的缩放位图；墨水屏上的笔画保持干净可读。
04
70 / 30 分栏正文仍在左栏七成，伴读摘要在右栏三成，互不遮挡；翻页、刷新波形沿用阅读页既有策略。
04 / DECOUPLED

听书开关，只管声音

听书与右栏摘要是两条独立的链路。关掉听书，摘要照常生成；开听书，也不会改变摘要内容。

听书 / TTS

由「听书」开关控制

设备的听书开关只控制是否朗读出声。朗读由独立的使能信号门控，跟随朗读开启、关闭即停。

0x1D 使能信号 · 断开蓝牙即停
摘要 / SUMMARY

不受听书开关影响

右栏摘要走独立的推送链路，只要伴读处于活动状态就照常请求、照常显示。关听书 ≠ 停摘要。

0x0A 摘要帧 · 独立门控
推流条件

两条链路取并集

只要「听书开」或「伴读活动」任一成立，手机就保持推流；因此静默阅读时翻页也能拿到新摘要。

tts_on ∥ companion_active
朗读仍依赖手机 App 保持蓝牙连接；断开连接会立即停止朗读。摘要生成依赖 App 在线与模型可用，二者前提不同，互不牵连。
05 / TIME & UPDATE

连上就校时，更新自己会查

步 5 收尾补上的两件小事：设备时间不再靠手动，版本新旧不必自己比对。

SET TIME蓝牙连接即下发

连接即校时

0x05 · 标准时间下发

  1. 手机 App 与设备建立蓝牙连接并订阅成功后，立即下发一次标准时间。
  2. 校时不再依赖先发一段文本；纯监听、不发文本的场景同样会校准。
  3. 连接保持期间，设备时间维持准确；无需在设备上手动设置。
日志里出现「校准设备时钟（连接即校时）……」即为校时帧已下发，属正常行为。
CHECK UPDATEApp v1.6.6 / 固件 26.11.30

检查更新

App 内按钮 · 设备联网 OTA

  1. App 内点「检查更新」读取正式版本源（apk-update.json）。
  2. 已是 v1.6.6 会提示「已是最新版本」；有新版则提示前往下载页。
  3. 断网或版本源不可达时提示「检查失败」，不会误报「已是最新」；本应用不自动下载安装。
  4. 固件侧在「设置 → 升级和恢复 → 联网 OTA」点「检查更新」，版本源已指向 26.11.30。
已是 26.11.30 的设备点 OTA 会显示「当前已是最新版本」，属预期结果，不是故障。
06 / REQUIREMENTS

伴读能跑起来的前提

下面几条不是功能缺陷，是这套方案本身依赖的条件。如实列出，便于排查。

01
仅安卓手机配套 App 只支持 Android；iOS 因系统限制不支持。Android 10/11 还需开启系统「定位服务」并授予位置权限，否则扫描不到设备。
02
手机与设备保持连接摘要由手机 App 调用模型生成后推送给设备；App 需点「连接并监听点词」保持前台保活，断开后摘要与朗读都会停。
03
需要你自己的 API key模型服务不内置账号。首次使用 AI 释义／伴读前，在「AI 释义设置」填入自己的 key（默认 DeepSeek）；base_url、model、提示词模板均可改。
04
固件与 App 需配套伴读能力落在 26.11.30 固件 ＋ v1.6.6 App 这一对上；请勿混用旧的 v1.6.5 及更早版本，旧版在多台设备并存时可能连错设备。
05
联网与额度摘要生成需要手机能联网、模型可用且额度充足。网络异常时右栏会停在占位态或显示「本次未生成」，不会伪造内容。
06
离线词典另装查词所需的 dict.bin 不在固件内，需自行放到 TF 卡根目录的 dict 文件夹；AI 释义与伴读摘要不依赖词典文件。
