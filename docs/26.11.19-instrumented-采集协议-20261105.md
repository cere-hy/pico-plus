## 二、K3 基线：三窗设计（纪律 19 的窗口构成）

> **v4 总纲**：三个窗的设计**一个字不改**，但**本轮只有一个窗出数**（W3）。
> W1 因「分子缺失」降为定性（§2.5-b），W2 因「无落窗判据、无判别量」休眠（§2.2）。
> **设计留着不是浪费**——它们是这个架构解决之后的现成作业单，届时不用重新想一遍。

「时延 ≤ 基线 max」这句话里，**基线 max 锚的是哪种情形**必须写死，否则 max 会锚成典型值。

### 2.1 W1 静止常态 —— **v4 降为定性（10 轮），v7 改成「按→锁屏→唤醒」循环，不产统计量**

**为什么降**：`t_key_take` 有机器量、`t_press` 没有（§2.5-b），分子缺失 ⇒ **P50/P95/max 全部不可算**。
硬算出来的只能叫「人眼猜测的分布」，写进判据就是把替代品当真件。

| 项 | 内容 |
|---|---|
| 本轮做法 | 首页「**短按 → 锁屏 → 等 2.5 s → 短按唤醒**」×10（§3.0-b）；每次只记**观感**：按下到画面出现有没有明显迟、有没有「慢半拍」、有没有「按了没反应要再按」 |
| 为什么不是「随手按」 | 电源键短按在普通页**就是锁屏**（`app_loop.c:1949`）——不锁屏就没有可感动作，没有可感动作就**没有观感可记**（§3.0-b） |
| 报什么 | 一句定性描述 + 次数；**不报 ms、不报分位** |
| 不做什么 | 不数 30 次（数了也没有分子），不测相位，不作 W2 的对照 |

**下表是「架构解决后」的形态，保留在案，本轮不执行**：

| 项 | 内容 |
|---|---|
| 场景 | 书架 / 首页静置，**无刷新进行中**，随手按 |
| 采什么 | 时延分布 → P50 / P95 / max |
| 样本量 | **目标 ≥ 30 次**；**P95 的报告门槛 = 20**（`N < 20` → P95 记「不适用」，只报 P50 / max；`N < 10` → 只报 max，P50 也不报） |
| 相位 | **随机**：不看屏、间隔 3–10 s 随手按 |
| 用途 | 给常态一个数，作 W2 的对照 |

**N 不预写，回来补不了**：P95 与 max 都是小样本敏感量——`N=10` 时 P95 就是次大值，报出来是个数、读起来是个错。
**上限不封（多按无害），下限必须写死**。

#### 2.1-b W1 两列附采 —— 解锁首帧新鲜度·**前基线**（v10，零成本，不进判据）

**为什么顺手**：W1 本身就是十次「**锁屏 → 唤醒**」循环。解耦批要一条「解锁首帧电量新鲜度」的对表，
而这条表缺的正是**解耦之前的形态**——没有前基线，解耦后看到「不一致」时分不清是「以前也这样」还是「新缺陷」。
十轮循环已经在跑，**多记两个数字，不多做一个动作**。

| 项 | 内容 |
|---|---|
| 两列 | **锁屏前**：短按锁屏那一下**之前**读状态栏百分比；**唤醒首帧**：唤醒后第一帧状态栏百分比 |
| 记录形态 | 现场单 W1 行画两列，十行：`轮 / 锁屏前 / 唤醒首帧 / 形态` |
| 预期 | **十轮全一致**。这个「全一致」本身就是前基线 |
| 归属 | 解耦批范围格「**解锁首帧新鲜度·前基线**」（回执 §3.2-a），**不进 K3 判据、不进六件套** |

**取数点按锁屏形态分叉（v10 读码结论；**v11 字段名统一为 `NORM` / `PIN`**，现场必须照此，不许「看不到了就算了」）**：

| 形态（字段值） | 唤醒首帧是什么 | 两列怎么取 |
|---|---|---|
| **`NORM`**（无密码） | 主页面首帧（`main_lock_boundary()` 置空基线后的完整绘制） | 直接取首帧状态栏百分比 |
| **`PIN`**（有密码） | **密码盘**——`ui_pinpad.c` **不画电量**（`percent` / `battery` 全文零命中） | 取「**解锁后首个含状态栏的主页面帧**」 |
| **`不可读+原因`** | 首帧读不到电量 | 如实写原因，**不许留空** |

> **字段取值以回执骨架 §1.2 为准**：旧稿写过「无PIN」，v11 统一为 `NORM`；两处是同一个形态，
> 但**现场只准写 `NORM`**，免得回来后一张表两套词。

> **两张表不能混算**：`PIN` 形态下两个读数之间隔着整个输码过程（数秒到数十秒），`NORM` 形态下只隔 2.5 s。
> 一致性结论可以各自下，**「差几格」不能跨形态比**——那是两个不同的时间跨度，比出来的差值没有同一把尺。

**为什么本形态下预期「全一致」（格 ② 的推论，写给解耦批看的）**：
`read_pico_pmu_poll()` = `refresh_core(false)`，**含 `QUICK_BATTERY` 读取**（`read_pico_pmu.c:621-623` → `parse_quick` → `qb_soc` + `quick_ok`）
⇒ **任何一次 poll 都刷电量**，不是只刷事件计数。
而解锁成功路径有 **`drain_events()` 的显式调用**（`lock_screen.c:134`），`drain_events` 的**首句就是 poll**（`:385`，队列空也至少走一次）
⇒ **解锁瞬间快照必然新过一次**。首帧的新鲜度**不靠 20/40 ms 环，靠这一句显式 drain**。

**这条结论的去向是解耦批，不是本轮**：摘掉环内 poll 之后首帧冻不冻，取决于 `:134` 那一句留不留。
两列基线的作用就是把这件事**先钉成对照**——解耦前全一致，解耦后不一致，变量就只剩这一个。

**封口**：两列是**给未来对照用的基线**，不是本轮的结论。十轮缺一轮，该形态基线**作废**（十轮是样本量，不是仪式）；
不一致时先分「跨输码的自然变化」与「快照陈旧」，**分不清就记「机制不明」，不许猜一个写上去**。

### 2.2 W2 整页刷新进行中 —— **v4：本轮休眠，假设移交 K3 的 overshoot 检验**

**休眠不是偷懒，是没有输入。** 三条理由各自独立成立，任何一条就够：

| # | 缺什么 | 后果 |
|---|---|---|
| 1 | 无 `disp begin/end` | **落窗判不了**——「按在刷新的哪一段」只能人眼，人眼置信不足以支撑任何断言 |
| 2 | `display_us` **不在产物里**（§1.1） | **同步/异步判不了**——这是唯一能分辨「刷新占住主循环还是只排队」的量 |
| 3 | 停手规则的输入也就是 `display_us` | **没有刹车**——只能靠预算硬停，30 次切页换不回一句可断言的话 |

**所以 W2 本轮不作为采数窗口**。它的机制假设不丢，改由 K3 的 overshoot 检验（§2.6）——**同一个问题，
不需要另开一窗**：若刷新真的把门拉长，K3 的样本自己会超上界；若没超，就说明没拉长。
W2 需要「人眼按准刷新窗口」，K3 只需要「随便按」，**后者便宜且判据更硬**。

#### 2.2-a 机制假设（保留，供 §2.6 分流用）

主循环内刷新（`app_loop.c:300` 等）在取键（`:1855`）之前，若刷新**同步占住**主循环，
按键在刷新期间进 FIFO、刷新结束才被取走，时延被拉长到
**「刷新剩余时长 + 门周期 + 逐事件 10 ms ACK 链」**。这是**推理，未实测**。

替代解释三条，各自对上界的影响不同（这张表在 K3 超上界时才真正被用到）：

| 替代解释 | 需要的证据 | 对上界的影响 |
|---|---|---|
| 刷新**不阻塞**主循环（异步/分段扫描） | `display_us` 远小于人眼可感的刷新时长 | 上界 = 常态包络（200 + S），刷新期无额外项 |
| 刷新太快、与 200 ms 门**极少重叠** | `display_us` ≪ 200 ms | 同上，且「超上界」本身变成罕见事件而不是系统性偏移 |
| 采样**相位**偏了（人眼「看到变化」晚于真实起点） | 人眼延迟估计 ≥ `display_us` | 只影响 W2 的样本，**不影响 K3**（K3 随机相位） |

#### 2.2-b 停手规则（v4：锚噪声底，不写「≈0」）

> **`display_us` < ±100 ms（= §五 的 ⑤ 件「人眼观测上限」）→ 立即停 W2。**

**为什么锚 ±100 ms 而不是「≈0」**：「≈0」没有定义，不同人读成 1 ms、10 ms、50 ms。
而 ±100 ms 是**本轮已经要申报的那个噪声底**——阻塞窗小于噪声底时，它造成的抬升在统计上
**不可分辨**，W2 必然无信息量。**同一个数干两件事**（K3 只断「超没超一个门」+ W2 停手），
比两个各自拍脑袋的常数好对账。

**本轮状态：预登记，无输入**（`display_us` 不在 bin 里）。这条规则写给**下一个带 `disp begin/end` 的构建**，
写在此处是为了它一出生就有刹车，不用再想一次。

#### 2.2-c 若仍想试一次（可选，不进判据）

预算 **≤ 10 次整页刷新**（原 30 次，因无刹车而砍）。产出只作「疑似」记录，**不进 K3 上界**、
不参与任何证伪。**不做也可以**——不做不产生缺口，因为缺口已经由「PENDING + 解锁条件」写明了。

### 2.3 W3 连按突发 —— **v4：主信号换成「单次 take 的事件数」**

#### 2.3-a 先修 v3 的方法缺口：事后读 `COUNT` 必然低估

连按 8 次 ≈ **800 ms**，中途 200 ms 门会 tick **三到四次**，每次 tick 把 FIFO 排空
⇒ 「每组连按**之后**立刻读 `COUNT`」读到的只是**最后一个窗的尾巴**（运气差时是 0）。
**峰值必然低估**，而且低估的方向恒定——这种偏差比噪声坏，因为它不会自己暴露。

**修法（载体已在产物里，零改动）**：一次 take 内打几条 `KEY_SHORT`/`KEY_LONG` 行 = 该 take **真实收走的 key 事件数**。
一次 take 内的多行就是**真实的单窗占用**，离线可复算，**比 `COUNT` 读数强一个量级**。

> **口径要写准**：只有 `KEY_SHORT` / `KEY_LONG` 两型会打日志，**同批里的电量/充电事件是静默消费的**
> （`take_key_action` 只对这两型 `ESP_LOGI`）。所以这个数是「**单窗 key 事件数**」，不是「单窗全部事件数」。
> 对 W3 够用（要的就是按键占用），但**不能拿它反推 FIFO 总量**——那会把静默事件当成不存在。

**这个「≠」不是免责声明，是证据力的来源（v5 补）**：正因为数是「key 事件数」而不是「FIFO 总量」，
静默事件（电量 `BATTERY_SAMPLE_READY`、充电边沿）不会混进来把 3 顶成 4，
**「单 take ≥ 4 ⇒ 门被拉长」才只可能来自门被拉长**。两条设计互为前提：口径越窄，证据越硬。
若哪天有人把它扩成「FIFO 总量」再读 4，这条旁证**当场失效**——4 条里可能三条是电量。
**账面必须把这两条放在一起读**，拆开读会各自显得保守、实则互相拆台。

| 项 | v3（作废） | **v4（本轮）** |
|---|---|---|
| 主信号 | 连按后读 `COUNT` 峰值 | **单次 take 的事件行数** |
| 载体 | 无（没有打印 COUNT 的地方） | **产物里的 `KEY_SHORT`/`KEY_LONG` 行 + `I (<ms>)` 前缀** |
| 偏差 | 系统性低估（读的是尾巴） | 无（数的是整批） |
| 可复算 | 否（当场读数，回家没法核） | **是**（日志留在串口抓包里） |

#### 2.3-b 分组判读规则（写死，否则「一次 take」也是模糊词）

> **同一 take = 连续若干 `KEY_SHORT`/`KEY_LONG` 行，`I (ms)` 非降、相邻差 ≤ 50 ms，且与下一组的首行间隔 ≥ 200 ms。**

**时间基只有一个：设备日志行前缀 `I (<ms>)`（v5 补）**。串口终端的行首时间戳含 PC 侧缓冲、
USB 批量传输与人读延迟——同一条日志在终端上可能晚几十到几百 ms 才出现，两条相邻行的终端戳
甚至可能倒序。用它算 50 / 200 两条阈值，等于**把分组规则建在另一个钟上**，而且偏得没有方向。
**终端戳只用于「翻到大致位置」，不参与任何计算**；两者混用会把 50/200 两条规则同时打歪，
且打歪的方式随抓包工具而变——**换一台电脑复算就对不上，而日志本身是对的**。

两条阈值各有出处，不是拍的：

- **≤ 50 ms**：批内每条事件要付一次 `event_ack`，而它内置 `vTaskDelay(10 ms)`（`read_pico_pmu.c:379`）
  → 3 条事件至少跨 20–30 ms；留一倍余量取 50 ms。
- **≥ 200 ms**：门周期 `APP_LOCK_POLL_MS`。**相邻两组不可能更近**，因为两组之间必然隔着至少一次门。

**同时记 `id=%u`**：`id` 单调递增即**入队顺序**（这是 v3 说的「白赚三样」里**唯一本轮真有载体**的一件，
见 §2.5-a）。若 `id` 出现跳号，说明中间有事件被别处吃掉（C1–C8 动点清单），当场记下来。

#### 2.3-c `COUNT` 的两条读法都不能用（一条作废、一条滞后）

| 读法 | 判定 |
|---|---|
| **事后读**（连按完再读） | **作废**——必然读到最后一个窗的尾巴，见 2.3-a |
| **中途读**（每按一次读一次） | **不可用**——但理由**不是**「抢 FIFO」（见下，我第一版写错了） |

**中途读为什么也救不了（v4 自纠，纪律 22 第五次执行——这次被执行的是本文件自己）**：

第一版写的是「打开 PMU 调试页即抢 FIFO」。**核实后不成立**：该页 `on_tick` 只调 `read_pico_pmu_poll()`
（PEEK，**窥视不是消费**），`ACK` 只在人点按钮时发生（`UI_PMU_HIT_ACK` / `EVT_CLR`）。
**页面不抢 FIFO。** 结论（`COUNT` 不可用）不变，理由换成三条更硬的：

| # | 事实 | 后果 |
|---|---|---|
| 1 | 门在主循环里，**与看哪一页无关** | 200 ms 一到照常排空；屏上的 `pending_events` 永远是**排空后的残值**，与「事后读」同病，只是采样更密 |
| 2 | 页面 `PMU_POLL_MS = 500`（`app_pmu.c:45`）= **2.5 个门周期** | 屏上数字至少滞后 500 ms，而计数每 200 ms 归零一次 → 读到 0/1 是常态，**读到 2 已是运气** |
| 3 | 墨水屏刷新慢于门周期 | 即使数据对，**画上去也来不及**——读数与按压无法同步 |

⇒ W3 不采 `COUNT`。**深度 8 不在真机上验**（v3 已移交宿主 K4 的桩注入）。

#### 2.3-d 三层处置（沿用 v3，措辞随主信号更新）

| 层 | 处置 | 内容 |
|---|---|---|
| **真机 W3** | **保留** | ① **单 take 事件数**（本轮主信号）；② 排队时延（人眼，不作断言）；③ `id` 连续性与跳号 |
| **宿主** | **移交** | **深度 8 与排水正确性 → 桩注入 8+ 事件，归 K4 断言**（本来住宿主真值表，不占真机） |
| **PMU 固件** | **文档级** | 溢出策略（满时先丢 INFO 再丢 NOTICE；`0x7F OVERFLOW` 带 `lost` 计数）→ **文档背书 + 未实测标注**，不进判据 |

**例外关闭（预查，断言级）**：`BATTERY_SAMPLE_READY` 运行档周期 ≈ **30 s**（关机未充 120 s / 关机充电 60 s）
→ 200 ms 窗内命中概率 ≈ **0.7%**，**顶不高单窗事件数**；`CHARGE_STATE_CHANGED` 只在状态边沿触发；
**W3 前拔电静置**（见 §三）再归零一层。

#### 2.3-e 反向旁证（v4 改判据式；v8 补补轮触发器）

v3 写「`COUNT > 3` ⇒ 门被拉长」，v4 改成**事件行口径**：

> **单次 take 出现 ≥ 4 条 key 事件 ⇒ 门被拉长**（刷新同步阻塞超过 200 ms）。

人手单窗上限 2–3（算术见 v3，不重复）。**出现 4 条，在本态内只有两个来源**（人手超 15 Hz 是第三条，
但现场一眼可辨、且不是「门」的问题，不列入判据）：

| # | 来源 | 判别 | 处置 |
|---|---|---|---|
| 1 | **门被拉长 / 主循环被长阻塞**（≥ 400 ms） | 没有 `KEY_LONG` 行 | **这就是要抓的证据** |
| 2 | **`KEY_LONG` 整屏 GL16 → 期间按键在 FIFO 堆积 → 刷完一次 take 全吐** | 同轮有 `KEY_LONG id=` 行 | **整轮作废**（§3.0-b） |

**注意方向**：**剔除作废轮后**出现即证据（v9 补限定），**不出现不构成反证**——4 条以上本来就罕见，采不到是正常的。

> **更正 v4 的一句「只有一种解释」（纪律 22 第十次执行，被执行者仍是本文件）**：v4 写「出现 4 条只有一种解释」，
> 是在**不知道 `KEY_LONG` 会整屏刷**的前提下成立的。读码后**本态内是两种**，但第 2 种**带签名且可剔除**
> （`KEY_LONG id=` 行）⇒ **剔除作废轮后，≥4 回到「只有一种解释」**。
> 结论（≥4 是强证据）不变，**成立条件补了一格**：不是「出现即证据」，是「**剔除作废轮后出现即证据**」。
> ——这条差别看着小，**写错就会拿一次自己按久的整屏刷去改一个没坏的门**。

| 项 | 内容 |
|---|---|
| 场景 | **关机对话框态**（§3.0-b；普通页短按即锁屏，连按必死），快速连按 8 次、**间隔 < 150 ms**（v6 写死；原「尽量 < 200」作废） |
| 采什么 | ① **单 take 事件数**（主信号）；② 排队时延（人眼，仅记录）；③ `id` 跳号 |
| 样本量 | **3 轮起 × 8 连按**（复现次数，不是「凑 8」）；**补轮触发器 = 合格间隔不足 10 → 补一轮，5 轮封顶**（v8：原「不设补轮」作废，理由见下） |
| 用途 | ① 定 K3 上界的 S 项（定阈取非嫌疑组，§2.3-f）；②③ 采数不进判据 |

**为什么把「< 200」收紧到「< 150」（v6，采样端的修正）**：

按压间隔逼近 200 ms 时，一次按压可能**刚好落在两个门之间** → 那一窗空、下一窗收两条 →
**相邻组间隔变成双周期 ≈ 400 ms**。而这时两侧组各只有 1–2 条事件，**都是非嫌疑组** ⇒
400 **干干净净地混进 `null_max`**，把 `T` 抬到 400，检测器对真实拉长**当场失明**。

`< 150 ms` 保证**每个 200 ms 门至少有一键**（150 + 人手抖动 < 200），从**采样端**杜绝双窗间隔。
这不是「更用力按」，是**把采样误差挡在数据之外**——检测器再巧，也救不了一份自己制造双周期的样本。

**代价要写明**：间隔收紧后每组只有 1–2 条事件，**≥ 4 签名更罕见**，旁证的灵敏度随之下降。
但旁证的定位本来就是「**出现即强证据、不出现无信息**」（§2.3-e），**不是**「按得够快就能抓到」——
所以这是**用一条本来就罕见的路，换掉一条会自己造假的路**，账是划算的。

**补轮触发器（v8：与 §2.3-f 的 ≥ 10 门槛咬合，不再互相打架）**：

算术摆开：8 连按 @ < 150 ms 跨约 **5–6 个门窗** ⇒ 每轮 **4–6 组** ⇒ 每轮 **3–5 个合格间隔**
⇒ 三轮 **9–15 个**——**相位不巧就落在 10 以下**。而 §2.3-f 要 ≥ 10 才给 `T`。

| 旧规则（v6） | 新规则（v8） |
|---|---|
| 「3 轮 × 8 连按，**不设补轮**」 | 「**3 轮起；合格间隔 < 10 → 补一轮；5 轮封顶**」 |
| 与 ≥ 10 门槛**互相打架**：够了才有 `T`，却禁止凑够 | 门槛成了**触发条件**：不够就补，补不动才降级 |

**封顶仍不足 ⇒ 走退化分支**（§2.3-f：记「无法判定」，升级为原始数据判读）。
**5 轮不是拍脑袋**：3 轮平均 12 个间隔，差一点的量级是「补 1–2 轮」；到 5 轮还不足 10，
说明**这台机器在惰性态下本来就出不了这么多组**（如相位长期对齐），再补是自我欺骗。

> **补轮只能由「合格间隔 < 10」触发**——不许为了「样本好看」「≥4 没出现」补轮。
> 触发器单向、可复算，和 §2.3-e 原来那条「样本要真，不要好看」是同一条纪律的两个面。

**逐轮记录，不合并**：每轮单独一行，记 ① 该轮**各 take 的事件数**（如 `2/3/1`）② 最大单 take 数 ③ 有无跳号。
合并成「最大值」会丢掉分布——而**「几次 take 各收了几条」正是 K3 的 S 项要的那个数**。

#### 2.3-f 检测器的假阳性结构（v5 立，v6 扩两处；`200 + S` 是**标称**阈值，null 分布可能压过它）

##### 问题：阈值里藏着一个没验过的假设

算术摆开：

| 项 | 值 | 出处 |
|---|---|---|
| 门 tick 首行到首行 | **200 ms**（量化） | `APP_LOCK_POLL_MS`（`app.h:210`） |
| **主循环抖动** | **未测**，页面 `on_tick` 等实工作，量级可能几十 ms | 本轮无载体 |
| `S`（批内服务） | `(N−1) × 13 ms ≈ 13–26 ms`（正常 `N = 2–3`） | §2.6 |
| 阈值 `200 + S` | **213–226 ms** | —— |

`200 + S` **隐含假设「抖动 ≤ S」**。抖动若 30 ms，正常组间隔的 null 分布就是 **200–230+**，
与阈值重叠——**检测器对噪声开门，首轮就可能产出一个假「成立」**。而假阳性比假阴性贵：
它会让人去改一个没坏的门，且改完「症状消失」（因为本来就没有症状）。

> **同一个式子，两种读法，账面必须注明用的是哪种**：
> 作为 **K3 上界**，`200 + S` 说的是「**一个事件**从入队到被取走最多等多久」；
> 作为**检测器阈值**，它说的是「**相邻两组首行**最多隔多久」。
> 数值同构（都 = 门周期 + 一次批内服务），因为「前一批服务完」正是「下一批开始等」的那一刻。
> **不注明读法，两个 200+S 会在同一份回执里互相指控**（纪律 21 的又一形态：词同、层面不同）。

##### 修法一：null 底取实测，不取标称

全部来自本会话日志，**不增现场负担**：

| 符号 | 定义 |
|---|---|
| `G_i` | **同轮内**相邻两组首行的 `I (ms)` 差：`t(first of take i+1) − t(first of take i)`。**跨轮不算**（轮间有人为停顿，不反映门） |
| **非嫌疑组** | 单 take 事件数 **1–3** 的组（≥4 见 §2.3-e，它本身是证据，不许参与定阈） |
| `null_max` | `max{ G_i : take i 与 take i+1 均为非嫌疑组 }`，**三轮合并取一个值** |
| `S` | `max{ 单 take 首末行差 : 非嫌疑组 }`，三轮合并 |
| **阈值 `T`** | **`max(200 + S, null_max)`** |

**两个数各有各的问题，所以都留着**：`200 + S` 回答「构造上最少要多久」（代码事实 + 批内服务），
`null_max` 回答「这台机器实际抖到多少」（实测）。**经验底只做下限保护，不替代结构项**——
若 `null_max < 200 + S`（正常情形），`T` 仍取 `200 + S`，不会因为样本里恰好没抖就放宽。

> **为什么两个都只取「非嫌疑组」**：见本节末「自指防护」——否则阈值会随现象一起涨，
> **检测器把自己的证据吸收掉**。这一句先给结论，理由在末节，因为读到这里的人正需要知道"用哪批样本"。

**为什么是「首 → 首」，不是「末 → 首」（v6 写死）**：

| 取法 | 间隔实际包含 | 偏差 |
|---|---|---|
| **首 → 首** | 前组服务时长 + 门等待 + 抖动 | **无偏**：首行相对 tick 的偏移是常量，相减相消；服务时长本来就该在间隔里 |
| 末 → 首 | 只剩门等待 + 抖动 | **系统性低估**：把前组服务时长从间隔里扣掉了，而它正是被测量的一部分 |

**方向写死之后，「相邻两组必须双非嫌疑」这条就从「必要」降为「过严」**：前组的服务发生在
**它自己首行之后**，不影响「本组首行 → 下组首行」这个差。**照用不改**——多丢几个样本、不偏方向，
**过严无害**。（放宽成「只要求后组非嫌疑」能多几个样本，但读者会怀疑前组污染，
争论成本高于收益。）

**样本门槛**：`null_max` 需 **≥ 10 个非嫌疑组间隔**。不足 → `T` 只作参考，本轮检测器记
**「未判定」**，**不记「未超限」**——3 个间隔的 max 不是上界，只是最大值。
（同 §2.1 的 P95 门槛：小样本敏感量不许当阈值。**补轮只能由「合格间隔不足 10」触发**，§2.3-e 已写死。）

> **诚实提示（v8 重算）**：8 连按 @ < 150 ms 跨约 5–6 个门窗 ⇒ 每轮 4–6 组 ⇒ 3–5 个合格间隔、
> 三轮 **9–15 个**——**相位不巧就差一点**。不足则按 §2.3-e **补一轮**（5 轮封顶）；封顶仍不足才记「无法判定」。
> **不许拿 9 个间隔硬算**——那是拿最大值冒充上界；**也不许为了凑 10 补轮**——触发器只有一个。

**null 污染检查（v5 补，与自指防护是一对）**：

> **若 `null_max > 200 + S + 100 ms`，`T` 不成立，检测器记「无法判定」。**

含义：所谓「正常组」的间隔已经超出任何合理抖动（100 ms 是本轮申报的**抖动预算**，推理级、未实测）。
这只有两种可能：① 这一轮本来就有门拉长，混进了非嫌疑组；② 机器在忙别的事。
**两种都让这把尺子失效**——此时若还拿 `T` 去说「未观测到」，等于用一把歪尺量完再宣布合格。
同理，**若三轮里没有任何非嫌疑组**（全是 ≥4），`S` 无值，检测器同样记「无法判定」。
**尺子自己歪了，量出来的数不算数。**

**为什么用 `max` 而不是 P90**：`max` 是**上界**，P90 是分位数——用 P90 就得声明
「`T` 不覆盖 10% 的正常情况」，那等于给假阳性留了一个写明的口子。**宁可让尺子粗一点，也不让它有已知的漏。**

##### 低侧守卫（v6 补，与高侧对称）

> **任一非嫌疑间隔 < 198 ms ⇒ 判「门外节拍」，该轮检测器记「无法判定」。**

`198 = 200 − 2 ms`（日志 1 ms 分辨率，两侧各 1 ms 截断余量）。理由：**门在结构上不允许低于 200 ms**
（`APP_LOCK_POLL_MS` 是下限，不是均值），低于 198 只能说明**这一拍不是主循环的门**——
40 ms 锁屏环、切页、快速重取，都是另一条链路（§3.0）。

**两侧余量的性质不同，账面必须分开写**：

| 侧 | 数 | 性质 | 为什么不能互换 |
|---|---|---|---|
| 高侧 | `+100 ms` | **推理级预算**（抖动未实测） | 是估计，将来实测后可收紧 |
| 低侧 | `−2 ms` | **结构零容忍**（分辨率误差） | 不是预算，是「结构上不可能」——给它留余量，等于承认门会短于 200 |

**这两种「余量」不是一回事**：一个给未知留，一个给测量误差留。**混着写，低侧看起来也可以放宽**，
而它恰恰是唯一不能放宽的那一侧。

##### 退化分支（v6 补，采纳审计）

| 情形 | 处置 |
|---|---|
| 合格间隔 < 10（含三轮全是嫌疑组） | 记「**无法判定**」，**升级为原始数据判读**：逐组列 `(首行时刻, 事件数, 间隔)` 进回执 |
| 全嫌疑组（无 `S`） | 同上，`S` 记「无」 |

**为什么不是「这轮白采」**：门若真被拉长，**组间隔本身就会说话**——`400 / 600 ms` 的间隔摆在那里，
不需要检测器替你判。**判据不跑 ≠ 现象没被看见**；K3 的结构项 200 ms 仍在，只是实测项标「无法判定」。
这一条防的是「检测器判不了 → 以为这轮白采」：**原始数据永远比判据长寿**。

##### 已知分辨极限（v6 登记，不修）

> 拉长约 **300–330 ms**、且按压间隔 **≥ 100 ms** 时：后组只有 3 条事件（不触 ≥ 4 签名），
> 间隔又低于 `200 + S + 100 = 326` 的污染线 ⇒ **被吸收进 `null_max`**，`T` 被抬到同一量级，检测器失明。

**为什么不修**：修复需要**事件侧同钟戳**（知道每组第一个事件何时入队），本仓没有（§2.5-b）。
**判词失明，但基线数仍诚实**——拉长就在「全体首到首 max」里，读的人看得见 300+，
只是检测器不会把它标成「成立」。

**登记的意义**：将来若有人说「检测器漏了一次 300 ms 的拉长」，答案是**这条已经写在纸上**。
**没登记的叫缺陷，登记过的叫边界**——两者的处置完全不同：前者要修，后者只需在读的时候记得。

##### 自指防护（v5 补，执行侧提出，请审计复核）

`S` 与 `null_max` **都只从非嫌疑组取**。若把 ≥4 的组算进去，等于**让被检对象参与定阈值**：
门被拉长 → 该批事件变多 → `S` 变大 → 阈值跟着涨 → **检测器把自己的证据吸收掉**。
这是整套判据里唯一一处「会让判据自证失效」的结构，写死在此。
（`S` 的原始定义「`N` 取 W3 实测最大单 take 事件数」在 §2.6 仍保留为**口径**，
但**定阈时用非嫌疑组的 `N`**——两者不是一回事：前者描述现象，后者定尺子。）

##### 修法二：成立需两次独立超限

| 观测 | 记账 | 是否成结论 |
|---|---|---|
| 0 次 `G_i > T` | 记「**未观测到**抬升」 | —— |
| 1 次 `G_i > T` | 记**线索**（附该组事件数 / `G_i` / `T`） | **否** |
| ≥2 次 `G_i > T`，**且分属不同轮次** | 记「**门被拉长成立**」 | 是 |
| 同一轮内多次 `G_i > T` | 合计 **1 次** | 否（同一次阻塞可跨多组） |
| 单 take ≥ 4 条（§2.3-e 旁证） | **出现即证据**，独立计 | 是 |
| 同一组既 ≥ 4 又超限 | **合计 1 次** | 不重复计数 |

**为什么必须「不同轮次」**：一次刷新阻塞会让连续几组都超限，那是**一个事件的多个视角**，
不是多次独立观测。**这是 W2 那条「不许拿一两个样本说证伪」的镜像**——那边防「没看到就说没有」，
这边防「看到一次就说有」。两条合起来才是完整的：**单次观测不构成任何方向的结论**。

**为什么两条门槛不同**：`G_i > T` 只是「偏大」，与抖动同量级，**单次分辨不开**；
`≥ 4 条` 是**结构性矛盾**（人手 10–15 Hz + 200 ms 窗 ⇒ 正常上限 3），一旦出现只可能是门的问题。
**特异性不同，门槛就不同**——同一条门槛套两种证据，结果不是放过噪声，就是丢掉真信号。

**「未观测到」四个字不许省成「没有」**：不超 ≠ 门没被拉长，只等于**这个会话没抓到**。
口径与 §2.2 的「未超即未观测到抬升」逐字一致。

### 2.4 相位为什么必须写死

**固定相位会系统性偏一端**：若每次都「紧跟取键之后按」，样本全落在门周期起点，测出来永远接近 200 ms；
若每次都「刚好在刷新中按」，测出来永远是最坏值。两种都不叫分布。

**v4 注**：下表是设计原意；本轮只有 W3 真跑（W1 定性、W2 休眠），相位策略随窗一起休眠，**规则不废**。

| 窗 | 相位策略 | 理由 |
|---|---|---|
| W1 | **随机**（不看屏、随手） | 覆盖整个门周期 |
| W2 | **相对刷新起点**（人为「看到画面开始变就按」） | 本窗要的就是最坏端，不需要分布 |
| W3 | **尽量密**（连按） | 本窗要的是 FIFO 非空态，不关心相位 |

#### 2.5-a `key_evt` 的挂点在哪（v3 预查，断言级）

「时延 = `t_key_take − t_key_evt`」这句话，**`t_key_evt` 打在哪**必须写死，否则可能量到另一个量。

| 问 | 结果 | 出处 |
|---|---|---|
| 事件帧带时间戳吗 | **带**：offset 4 `u32 timestamp_ms`，**PMU 开机毫秒，不是 UTC** | `llms-full_zh_cn.md:127`、`:87` |
| 宿主解析了吗 | **已解析**：`parse_event` 整块 `memcpy` 进 `pmu_event_t`，`s_snap.event` 里**现成**（含 `severity`） | `read_pico_pmu.c` `parse_event`、`protocol.h:258-269` |
| 有 INT / ISR 吗 | 有 `CW_INT`（STATUS bit13），但**本仓无 ISR**（无 `gpio_isr`）→ **纯 poll 架构** | 文档「CW_INT 为低 → 读 0x84」 |
| `arg0` 是什么 | `KEY_UP` 的 arg0 = **按时长**；`KEY_SHORT / LONG` 的 arg0 = `held` | 文档 `:131`、代码日志 `held=%u` |

**结论：有戳，但跨钟。** PMU 钟源是 LSI，精度 **±1–2%**——10 s 漂 **100–200 ms**，**与要测的量同量级**
⇒ **跨钟相减不可用于时延**。所以时延主定义仍是**人眼降级**——结论与预判一致，**理由换掉**：
不是「没有戳」，是「戳的钟不可信」（纪律 22：结论可以不变，理由必须对）。

**v3 说「白赚三样」，v4 核完产物只剩一样**——这个更正比它听起来重要：

| 量 | v3 判定 | **v4 实际** | 理由 |
|---|---|---|---|
| 按压时长 | 白赚 | **无载体** | 需 `KEY_UP.ts − KEY_DOWN.ts`，日志里没有 `evt_ms` |
| 连按间隔 | 白赚 | **无载体**（只能粗估） | 同上；由取键时刻反推间隔，误差 ±200 ms，只够分「密 / 中 / 疏」三档 |
| **入队顺序** | 白赚 | **有，但换载体** | 不靠时间戳，靠 **`id=%u` 单调性**——`id` 就在产物里 |

**代价申报（给将来那一次，本轮不动）**：`sev` / `evt_ms` 只需 `take_key_action` 里**多一行 `ESP_LOGI`**
（数据已在 `s_snap.event`，零 I2C、零结构改动）。**本轮不构建、不改码**；「申报过成本的构建期一行」
与「扩桩」的层面划分见 §六。

#### 2.5-b **分子缺失，不是精度差**（v4 新增，本批最硬的一条）

v3 把时延定义写成人眼 `t_key_take − t_press_observed`，噪声底 ±100 ms。**v4 核完后这句要收得更狠**：

| 项 | 内容 |
|---|---|
| `t_key_take` | **有，且是机器量**（日志前缀 `I (<ms>)`，1 ms 分辨率） |
| `t_press` | **没有**——PMU 戳跨钟（LSI ±1–2%），人眼只能给 ±100 ms 的**猜测** |
| ⇒ 结论 | 时延 = 一个机器量 **减** 一个猜测，**差值不是一个测量值**。毛病不在精度，在**分子缺失** |
| 加一行日志能救吗 | **不能**。`evt_ms` 进日志也只是把「猜测」换成「另一个钟」，跨钟相减照样作废 |
| 唯一剩的路径 | **外部仪器**（按键线上挂逻辑分析仪，与串口时间对齐）——**本轮不做，不入判据** |
| 因此 | **W1 本轮不产统计量**（P50/P95/max 全部不可算），只产**定性观感**；K3 走上界两段式（§2.6） |

> **这一条写下来是为了不再重复试**：三次想给 K3 找机器量，三次都撞在「两端不同钟」上。
> 架构层面的事实是：**本仓无 ISR、无同钟按压时刻**，所以「按下到取走」的时延**在这个固件里测不出来**，
> 能测的只有「批内服务时长」和「门有没有滑」。**承认这一点，K3 反而能定稿。**

**为什么 `held` 也救不了（v5 补，写给三个月后的自己）**：

`held` 是**按压时长**，不是按压时刻。想由它反推 `t_press`，只能写：

```
t_press ≈ t_detect − held
```

而 `t_detect` 是「这条事件被读到的时刻」，`t_detect − t_press` **正是要测的 FIFO 延迟本身**。
⇒ **用 `held` 算时延 = 用被测量定义被测量，循环。**

而且 `held` 属于**PMU 侧**的时长（`arg0` = 按时长），`t_detect` 属于**ESP 侧**的毫秒——
**跨的仍是同一对钟**（LSI ±1–2%），只是把「减一个猜测」换成「减一个跨钟量」，精度不会变好。

**`held` 在本轮的唯一用途**：核对折叠语义——`take_key_action` 只认第一个 `SHORT`、`LONG` 覆盖，
所以**分发的 `held` 应等于批内第一个 `SHORT` 的 `arg0`**（K4 的载荷断言）。
**它不进任何时间计算。** 这一行写下来，是为了防止有人「发现」`held` 可以算时延，
把已经关上的门再打开一次——**第二次打开的成本比第一次高，因为这次要推翻一份写过的结论。**

**时延定义（v3 写死挂点，不许模糊）**：

> `t_key_take`（机器量，日志前缀 `I (ms)`）**减去** `t_press`（人眼 ±100 ms 的猜测）
> = **只作定性记录，不产数、不进判据**。K3 的阈值里**没有这一项**（§2.6 只用 `200 + S`）。
> 这一定义的作用不是「怎么算」，是**说明为什么不许算**（§2.5-b）。

**字段用途（v4 收口）**：

| 字段 | 本轮 | 将来 |
|---|---|---|
| `I (<ms>)` 日志前缀 | **取键时刻，主用**（分组 + `S` 项） | 同 |
| `id=%u` | **入队顺序**（替代时间戳单调性） | 同 |
| `held=%u` | 短按/长按载荷，核对折叠语义 | 同 |
| `evt_ms` | **无载体** | 同钟差分（间隔、按压时长）——但**救不了时延**（§2.5-b） |
| `sev` | **无载体** | 丢弃优先级佐证 |

### 2.6 判读规则（采完当场填，不回家补）

| 问 | 答法 |
|---|---|
| **K3 上界取什么** | **`200 ms`（结构项）+ `S`（实测项）**。`S` = **非嫌疑组 span 的 max**（单事件组 span = 0，不入；§2.3-f）；`N` 的**现象口径**仍记 W3 实测最大单 take 数 |
| 为什么不是「实测 max」 | `t_press` 无同钟载体 → **分子缺失**（§2.5-b），实测 max 算不出来；而 `200 ms` 是**构造**（`APP_LOCK_POLL_MS` 写死），不是估计 |
| **检测器阈值 `T`** | **`max(200 + S, null_max)`**，`null_max` 取非嫌疑组相邻组间隔的实测上界（§2.3-f）。null 底不足 10 个间隔 → 记「未判定」 |
| **K3 断什么** | 组间隔超 `T` ⇒ **门被拉长**（刷新同步阻塞）。这正是 §2.2 的假设——**不用另开窗就能判** |
| **成立门槛** | **≥2 次独立超限、分属不同轮次**；单次只记线索，记采数不记结论（§2.3-f） |
| 刷新期最坏合法值 | **PENDING**；解锁条件**不是**「加一行日志」，而是「同钟按压时刻」或「外部仪器」（§2.5-b） |
| W1 报什么 | 只报**定性观感**（有没有明显迟、有没有慢半拍），**不报 P50 / P95 / max** |
| severity | 不采（无载体），走文档线：`llms-full:129` 只给「先丢 INFO 再丢 NOTICE」，**未列按键级别** |
| 单 take 事件数 | 逐轮记**分布**（如 `2/3/1`）；最大单 take 数只作**现象口径**（定阈不用它）；**不问「到没到 8」** |

#### 2.6-a 判词与基线分离（v6：**数是观测，判词是解释**）

**任何判词下，基线数照填。** 「无法判定」不免除填数，只改口径注——这是本小节的唯一目的。
它防的是一个很自然的误用：**判不出来，就干脆不填**，于是回执上只剩一句「无法判定」，
下一个读的人连现场发生过什么都不知道。

| 判词 | 触发 | K3 落账口径 |
|---|---|---|
| **未观测到** | 超限合计 < 2 轮 | 全体首到首 max +「常态包络」 |
| **成立** | ≥ 2 次超限、分属不同轮 | 全体首到首 max +「含拉长期」 |
| **无法判定** | null 污染 / 门外节拍 / 合格间隔 < 10 / 全嫌疑组 | 全体首到首 max +「机制不明」 |
| **作废** | 锁屏触发（`lock` / `drain` 行在证） | 受影响窗重做（不填数） |

**三个数各是什么，不许混读**：

| 数 | 定义 | 用途 | 随判词变吗 |
|---|---|---|---|
| `T` | `max(200 + S, null_max)` | **检测器阈值**（判「超没超」） | 变：无法判定时**无 `T`** |
| `200 + S` | 结构项 + 批内服务 | **K3 断言上界**（落码填常量） | **不变** |
| 基线数 | **全体组间隔 max**（含被拉长的组） | **观测记录**（人读） | **不变，永远填** |

**为什么必须分开**：`T` 是本轮的**尺子**，基线数是**被量的东西**，`200 + S` 是**断言用的上界**。
三者碰巧都在 200 附近，混着写，一张回执里会出现三个「200 多」互相打架（纪律 21 的又一形态：
词同、层面不同）。**口径注写在基线数后面**，只用三个词：`常态包络` / `含拉长期` / `机制不明`。

**两小件（v6 随行）**：

1. **`S` 取非嫌疑组 span 的 max**（包络）；**单事件组 span = 0，不入**——一条事件的组没有「批内服务」，
   放进去只会把 max 拉成 0。`S` 至少要 2 条事件的组才算得出来。
2. **W1 的间隔不进 `null` 池**：W1 是**锁屏循环**（≥ 2.5 s 一轮，§3.0-b），组间隔由**按压节奏**主导、且夹着锁屏/唤醒两段 20 ms 环，不是门周期样本。
   混进 `null_max` 会直接把 `T` 抬到秒级——**样本来源不同，池子必须分开**。
   （W1 本就不产统计量（§2.1），它的间隔只在「有没有按」上有效，不在「门多久」上有效。
   **同名不同源，是 null 池最常见的污染方式。**）

### 2.7 本轮各窗能报什么（v4 重排：统计量让位）

| 窗 | 本轮状态 | 能报 | 不能报 |
|---|---|---|---|
| W1 静止常态 | **降为定性**（10 轮锁屏循环，§3.0-b） | 观感描述 | **P50 / P95 / max**（分子缺失） |
| W2 刷新中 | **休眠** | 无（可选 ≤10 次，只作「疑似」） | 任何进入 K3 上界的数 |
| W3 连按 | **本轮主产** | 单 take 事件数**分布**、**组间隔分布与 `T`**、**判词与基线数**、`id` 跳号 | `COUNT`（读法已废，§2.3-c） |

> **注意**：「无法判定」时**仍要填基线数**（§2.6-a）——不填不在「不能报」之列，是**必报**。

**v3 的样本门槛表（30 目标 / 20 报 P95 / 10 只报 max）保留在案，但本轮不适用**——
那些门槛解决的是「小样本能不能报分位数」，本轮的问题是**没有分子**。门槛再严也救不了不存在的数。
表留给「架构解决后」那一次，届时不重新设计。**30 与 20 的分层（采集目标 vs 报告门槛）仍成立**，
只是本轮两项都为空——**空不是矛盾，是没有数**（纪律 21 的第五次形态）。

## 三、会话顺序（v8：0 步硬前置 + 补轮；两账 + 一项，W2 休眠）

### 3.0 前置：自动锁屏（**验收卡 0.3 的等价行**，v6 **硬前置**）

**为什么是硬前置**：本会话有五段无操作（插电静置 5 min、拔电 30 s、三次 W3 之间的停顿），
而设备档位只有 **1 / 5 / 10 分钟**（`settings.c:221` 只认这三个值，外加关闭）——
**1 分钟档在静置段内必然触发，5 分钟档只在边缘**。更关键的是：
`idle_blocked` 的豁免项里**没有「充电」**（`app_loop.c:2111`：USB 存储 / 传输 / 升级 / 触摸中），
**插着电不豁免锁屏**，拔电也不新增豁免——不能指望「插电段安全、只有拔电后危险」，
**整个静置段都在锁屏射程内**。不关它，等于**把会话设计成自毁**。

> **为什么这不构成「改了被测系统」**（先答这一句，否则下一个人会以为「关设置 = 环境不可比」）：
> 锁屏档位**不在被测路径上**——门（`APP_LOCK_POLL_MS`）、取键（`take_key_action`）、采样都不读它。
> 关掉它只是**移除一个竞争的消费者**，被测系统的行为一字不变。**改设置与改被测对象，是两层。**

**锁屏态的两条环（20/40 对账，v6 读码确认）**：

| 环 | 周期 | 在哪 | 怎么对待 FIFO | 日志形态 | 后果 |
|---|---|---|---|---|---|
| **静默等待环** | **20 ms** | `sleep.c:158-179` `app_lock_wait_key_idle()` | 每拍 `drain_events()` **逐条 ACK** | `drain <TYPE> id=<n>`（无 `held`） | 按键**不产生 take 行** → 样本消失 |
| **PIN 界面环** | **40 ms** | `lock_screen.c:120`（**仅 `lock_pin_enabled()` 时**） | `take_key_action()` **取键，取到即 `cancel` 退出认证** | 正常 `KEY_SHORT id=.. held=` | 只留 **1 条** take，其余被随后的 800 ms 静默窗 drain |

> **20/40 对账结论：是两条环，各管一段。** 20 ms 管「锁屏前静默 / 解锁前后」，40 ms 管「密码界面」。
> 两个数共享「锁屏」这个名字，但**消费者不同、节拍不同、日志形态不同**。
> 此前把它们记成一个数，是**两个真相共用一个名字**——这次不是「词同、层面不同」，
> 是**词同、物不同**（纪律 21 的反面形态，同样会让人对着账猜半天）。

**对 W3 的两种形态，破坏都是「缺样本」，但有密码会多混一条真行**：

| 形态 | 日志表现 | 对主信号的破坏 |
|---|---|---|
| **无密码（出厂默认）** | 只有 `drain KEY_SHORT id=N`；**无 take 行** | **样本全部消失** → 计数偏低、`id` 跳号（还会被 §2.3-b 误判成「被别处吃掉」） |
| **有密码** | **第一下**进 40 ms 环被 `take`（正常 `KEY_SHORT held=`），**随后 800 ms 静默窗把其余按键 drain 掉** | **8 连按里通常只有 1 条进 take**，其余进 `drain`；那 1 条的间隔由**人手与 800 ms 静默窗**决定，**不是门** |

**有密码形态更危险在哪**：它**混进一条真的 take 行**。数据「看起来是有的」，形态也正常——
只有把 `I (ms)` 与前后 `drain` 行连起来读，才知道这一条不是门给的。
**这就是 0.3 必须是硬前置的理由**：不是「可能干扰」，是**两种形态都在改写主信号**，一种全拿走，一种拿走大半还留一条。

> **撤回上一版的一条推断（纪律 22 第八次执行，被执行者是本文件刚写的 v6 草稿）**：
> 草稿里写「有密码时 8 连按会被 40 ms 环并成一组、单 take 数虚高到 8、伪造 ≥ 4 签名」。**读码不成立**——
> `lock_screen.c:120` 的 40 ms 环**一旦取到键就 `cancel=true` 退出认证**，随后回到
> `app_lock_wait_key_idle(800)`：**用户继续按，这 800 ms 内的按键全部被 `drain`**。
> 所以真实形态是「**1 条 take + 其余 drain**」，不是「8 条并组」。
> **结论（锁屏段作废）不变，机制写错了**——若不改，下一个人会拿「虚高」去解释一段实际偏低的数据。

> **更正上一版的一句说法（纪律 22 第六次执行，被执行者仍是本文件）**：v4 讨论时写「日志行不带
> 『此时在锁屏』标记，事后无法剔除」。**读码后不成立**——`lock LIGHT` / `unlocked` 与 `drain KEY_*`
> 都在日志里，**可以事后判别**。**但结论不变**：判别得出来 ≠ 修得回来。缺的样本补不回、
> 被 40 ms 环取走的那一条、以及随后被 drain 的若干条，都补不回来，所以仍然是**作废重来**，不是「标一下继续用」。

> 对应验收卡模板 `0.3` 原句：「**会干扰本轮的设备设置**（如自动锁屏）调到不干扰档；
> **记原档位，测后还原**」。本轮把「如自动锁屏」这个举例变成**必办项**——因为它不是"可能干扰"，
> 是**已经读码确认会吃掉样本**。

**处置（二选一，写死）**：

| 方案 | 动作 | 说明 |
|---|---|---|
| **A（首选，本轮默认）** | 设置 → **自动休眠锁屏** → **关闭**；**记原档位**（1 / 5 / 10 / 关闭）；**会话结束还原** | 验收卡 0.3 的等价行。档位是 NVS 持久项，不还原就是改了用户设备状态 |
| **B**（保持出货状态不关） | 只用于「顺便验锁屏」；触发即按下表作废 | **不接受「带锁屏态继续按」**。**方案 B 下 W1 不可执行**：W1 本身就是「按→锁屏→唤醒」，自动锁与手动锁在日志里分不开（都出 `lock LIGHT`），观感也无从归因 ⇒ **B 只做 W3** |

**方案 B 的作废规则**：

> **判别到锁屏 ⇒ 该段 W1 观感作废、W3 该轮作废并重来；不作废则整轮数据不进账。**

**判别三源**（都在日志里，不需要现场盯屏）：

1. `lock LIGHT` / `unlocked` —— **锁屏标记本身**，对两种形态都有效；
2. 出现 `drain KEY_SHORT` / `drain KEY_LONG` —— 正常取键路径只出 `KEY_SHORT`，**不出 `drain KEY_`**。
   **无密码形态是「只有 drain」，有密码形态是「take 与 drain 交替」**——两者都算命中；
3. `id` 跳号，且跳掉的 `id` 恰好出现在 `drain` 行里。

> **drain / lock 行的真正价值（v6）**：它们**救不了样本，但救得了报告**——作废窗口能写出归因
> （「这一段作废：12:03:41 `lock LIGHT`，随后 6 条 `drain KEY_*`」）。
> **没有归因的作废，三个月后看起来像「那天数据不好」；有归因的作废，是一条可复核的现场记录。**

### 3.0-b 键位与可连按态（v7：审计给的「用翻页键」**前提不成立**）

**读码三条（断言级）**：

| # | 事实 | 出处 |
|---|---|---|
| 1 | **PMU 事件里没有键位字段**：`pmu_event_t` 只有 `event_id / type / severity / timestamp_ms / arg0 / arg1`；取键只读 `type` 与 `arg0`（= `held`） | `read_pico_pmu_protocol.h:255-269`、`read_pico_pmu.c:401-406` |
| 2 | **屏下三个键区是触摸**：`KEY1/2/3` 按坐标判（`ui_key_hit_test`），走 CST836U，**不产生 `KEY_SHORT`** | `app_loop.c:2012`、`ONBOARDING.md:61` |
| 3 | **电源键短按在普通页 = 锁屏**：无 `on_power_short` 时直接 `prepare_lock` + `enter_lock_and_sleep` | `app_loop.c:1949-1965` |

**全仓只有 `app_book` 实现了 `on_power_short`**（`app_book.c:10074`），且要 `app_settings_reader_power_turn()` 为真才生效（`:10082`）。

> **结论**：「用一个不锁屏的翻页键去连按」**这条路不存在**。能产出 `KEY_SHORT` 的键，正好是一按就结束会话的那个键。
> 审计的**动机完全正确**（防会话杀手），**载体选错了**——这不是措辞问题，是装置问题。

**可连按态只有一个：关机对话框**（`power_dialog_open`）。

| 事实 | 出处 | 含义 |
|---|---|---|
| 短按落在 `else if (!power_dialog_open)` 的**否定分支** | `:1949` | 动作被吃掉：不锁屏、不关机、不重绘 |
| 但 `read_pico_pmu_take_key_action()` 已在同一拍执行 | `:1858` | `KEY_SHORT id=.. held=..` **照打**——主信号不受影响 |
| 门条件**不看** `power_dialog_open` | `:1855-1857` | 200 ms 节拍照跑 |
| `idle_blocked` 含 `power_dialog_open` | `:2112` | 顺带不会自动锁屏 |
| 对话框无超时 | `ui_power_dialog.c`（无定时器） | 开一次够撑完三轮 |

#### 对话框自己怎么对待按键（v8 必补：全场唯一「读错就毁会话」的断言，端点 = 代码本身）

**问题**：上面的行号证明的是「主循环的锁屏支被跳过」，**没有**证明「对话框拿到短按之后不动作」。
若对话框把短按读成「取消」（关框重绘）或「确认」（关机），**第一轮第二按就杀死会话**。
按家族规则，这一格的端点必须是代码——**引用如下，不是转述**：

| # | 事实 | 出处 |
|---|---|---|
| 1 | `ui_power_dialog_feed()` 的**输入只有触摸**：`ctx->touch` / `ctx->pressed` / `ctx->released`；**全文无按键字段引用**（无 `key_evt`、无 `KEY_SHORT`） | `ui_power_dialog.c:48-123`（`:52-54` 早退、`:63` 取 x/y、`:64/:100/:114/:119` 读 pressed/released） |
| 2 | 三个动作全由**触摸命中**触发：滑条过 `UI_POWER_SLIDE_COMMIT` → `SHUTDOWN`；圆钮**抬手** → `RESTART` / `CANCEL` | `:101-103`、`:114-117` |
| 3 | 短按在 `:1949` 的 `else if (!power_dialog_open)` 里**已被判掉**，对话框根本收不到这个事件 | `:1949` |

> **结构性结论**：对话框**没有按键输入通道**，所以「它会把短按读成取消」在类型层面就不成立——
> 不是「行为上恰好不动作」，是**喂不进去**。这一格可以封板。

**但有一处会毁一轮，且比锁屏更常发生（v8 读码发现）**：`KEY_LONG` 分支**不看 `power_dialog_open`**——
判到 LONG 就直接进 `else`（`:1896`），重新 `ui_power_dialog_reset` + `ui_power_dialog_draw` +
`update_display_area_with(GL16, 整屏)`（`:1928-1937`）。即：**按久一点 = 一次整屏 GL16 刷新。**

| 后果 | 说明 |
|---|---|
| **会话不终止** | `power_dialog_open` 仍为 `true`，人还能继续按——所以它不杀会话，专杀**数据** |
| **该轮作废** | 整屏刷新阻塞主循环，**组间隔被拉到秒级**，而且**长得像「门被拉长」** |
| **判据** | 日志出现 `KEY_LONG id=` ⇒ **该轮作废重来**，归因写「第 n 轮按下未松手」 |

**它不止「看起来像」拉长——它精确打在检测器的签名上**（v9 补，机制链）：

```
按久 → KEY_LONG → 重画对话框 + update_display_area_with(GL16, 整屏)
     → 整屏刷新期间主循环被占住，不取键
     → 这几秒里按的键全在 FIFO 里排队（深度 8）
     → 刷完第一次 take 循环把队列一次吐尽
     → 单 take 出现 4～8 条 key 行  ⇒  正好命中 §2.3-e 的「≥4 ⇒ 门被拉长」
```

**这就是它比锁屏更危险的地方**：锁屏让样本**变少**（一眼看得出），`KEY_LONG` 让样本**变成我们正在找的那种形状**。
**假阳性伪装成证据，比假阳性伪装成异常难发现得多。**

**三条操作确认（v9 写死）**：

| # | 确认 | 含义 |
|---|---|---|
| 1 | **开框那一次长按是全会话唯一许可的 LONG，且发生在窗口起点之前** | 窗内出现任何 `KEY_LONG id=` 行 = **该轮作废重来**，归因写「第 n 轮按下未松手」 |
| 2 | **作废轮剔除后签名空间是干净的**：本态内 ≥4 只剩「门被拉长」一个来源 | 剩下的 ≥4 **全部是真拉长证据**——检测器在惰性态**无已知假阳性源** |
| 3 | LONG 阈值在 **PMU 侧不可见**（本仓无毫秒常量）⇒ **行为约束 + 事后行判据是唯一可行组合** | 这个「只能写成行为约束」的**诚实标注本身要留档**，别让后人以为我们忘了写数 |

> 第 2 条的**边界要一起写**：它成立的前提是「惰性态 + 作废轮已剔除 + 拔电静置 30 s 已过」。
> 三者缺一，就退回「出现即线索」。**好消息写在这里，边界也写在这里**——只写前半句，等于给下一个人一个过期的许可证。

**所以 W3 的按压是「点」不是「按」**：按下即松、指头抬离键面，**不按住**。
`KEY_LONG` 的阈值在 **PMU 侧**（本仓只有事件码 `PMU_EVT_KEY_LONG`，`read_pico_pmu_protocol.h:210`；
全仓无长按毫秒常量）⇒ 规则只能写成**行为约束 + 事后判据**，**不能**写成毫秒数。
**这是本轮唯一一条「假阳性主要来自操作者自己」的项**——写在这里，比写在判读章程里有用。

**同理，手不许碰屏**：对话框的 `CANCEL` / `SHUTDOWN` / `RESTART` **全由触摸触发**（上表第 2 行），
任何一次误触都会关框或关机。设备**平放**，W3 期间只有手指上下点电源键。

**现场写法（W3）**：首页 → **长按**电源键直到对话框出现（不触摸）→ **等 3 s**（对话框那次 GL16 整屏刷新落定，`KEY_LONG` 也出窗）→ **3 轮起** × 8 连按，间隔 **< 150 ms**、**每次点按不按住** → 不足 10 个合格间隔则**补轮（5 轮封顶）** → 触摸「取消」退出（一次整页重绘，W3 已收工）。

**代价必须写明（本轮口径的适用范围）**：`power_dialog_open` 时 `on_tick` 被跳过（`:2098`）、页面不重绘
⇒ **本轮 null 是「惰性态 null」**。它证明的是「**空载**下门不超 `200 + S`」，**不能**外推成「翻页负载下门不超」
——后者靠 §2.3-e 的 **≥4 旁证**去撞。本基线的**主用途是同态前后对照**（解耦前后都在这个态测），不是普适上界。

**W1 改用「按 → 锁屏 → 唤醒」循环**（惰性态没有可感动作，观感无从谈起）：
首页 **短按（记「按下到画面出现」）→ 等 ≥ 2.5 s → 短按唤醒**，共 10 轮。
2.5 s 是为了越过 `APP_LOCK_IGNORE_BOOT_MS = 2000`（`sleep.c:555`）——不等，第二下会被当开机忽略
（日志 `ignore boot power-key action`），**观感与日志都对不上**。

**W1 与 W3 必须分窗**：W1 段必出 `lock LIGHT` / `unlocked` / `drain KEY_*`；W3 的「三源作废」判据
**只看 W3 起始时间戳之后**的行。W3 开窗前要求 **≥ 10 s 内无 `lock` / `drain` 行**，否则不开始
——否则 W1 的尾巴会被误判成「W3 期间锁屏」。

> **撤回 v6 的一条顾虑（纪律 22 第九次执行，被执行者仍是本文件）**：v6 写「`quick_lock_requested` 短路支
> 可能产生计划外 take」。**读码不成立**：`:1858` 是三元式
> `quick_lock_requested ? READ_PICO_PMU_KEY_SHORT : read_pico_pmu_take_key_action()` ——
> **短路支根本不调 `take_key_action`、也不 poll**，一条日志都不会多；且它的触发源是**快捷菜单的触摸项**
> （`:1470`），不是电源键。低侧守卫的归因清单因此去掉 `quick`，只留 `lock` 与 40 ms 节拍两项。

### 3.0-c 主发现：PIN 环是 `s_snap` 的**事实采样属主**（v7 登记，不阻塞本轮）

**链条（已证事实拼接，断言级）**：`take_key_action` 循环首句 `read_pico_pmu_poll()`（`:397`）
→ `poll()` = `refresh_core(false)`（`:650-652`）→ 读 IDENTITY / STATUS / QUICK_BATTERY / EVENT_COUNT / EVENT_PEEK。
PIN 环每 40 ms 调一次 `take`（`lock_screen.c:120`）⇒ **PIN 认证期间 `s_snap` 每 40 ms 被刷新一次**
（且每拍两次 `poll`：`:120` 显式一次 + `take` 内部一次 ⇒ 总线约 50 Hz）。

**这是便车债的第三位乘客**：前两位是电量值、按键路径本身；第三位是**锁屏链的采样新鲜度**——
它靠的不是自己的采样节拍，而是「有人在取键」这个副作用。

**消费面（本轮已 grep，断言级）**：`lock_screen.c` 与 `ui_pinpad.c` **零** `read_pico_pmu_get()` 命中
⇒ **PIN 界面不消费 `s_snap`**。所以**当前不构成缺陷**，是**隐性依赖**。
更广面（解锁后首帧 `app_home.c:313` 读 pmu、BLE 状态上报）**未穷举**，记入解耦批读码格。

**两处更正 v6 的说法**：

| v6 说法 | 读码事实 | 更正后 |
|---|---|---|
| 「无 PIN 的普通锁屏今天就没有采样（drain 不 refresh）」 | `drain_events()` 也 `poll()`（`:385`）⇒ 20 ms 环**每拍都在刷** | **普通锁屏也有采样**。解耦后 PIN 期不是「跌回普通锁屏」，是**比普通锁屏更陈**（20 ms vs 冻结） |
| 「PIN 环取键功能不变」 | `take` 现在靠**自己 `poll`** 把事件填进 `s_snap.event` 再读 | 瘦身后 `take` 必须**自足**（直读 COUNT→PEEK→ACK，不依赖 `s_snap.event` 已被谁填好），否则**PIN 界面按不动**（认证退不出去） |

**落码要求（比电量显示更硬的验收面）**：`take` 瘦身时**不许保留 `s_snap` 依赖**；
验收 = 真机 PIN 界面**电源键可退出**（30 s 内），且 `KEY_SHORT` 行照出。
—— 这条写进解耦批 K6.1，因为它才是「第三方接管」的真正代价。

> **半句（v7，读码事实）**：全仓**没有**与锁屏分离的「自动休眠 / 自动关机」**定时项**——设置里只有
> 「自动休眠锁屏」（1 / 5 / 10 / 关闭，`settings.c:221`）与「关机睡眠」（决定关机是深睡还是彻底断电，
> `app_device_settings.c:1148-1151`，**不是定时器**）。所以**关掉前者就是全部**，没有第二个开关要关。
> 若将来新增独立项，按 0.3 同样处理——但**现在不写「如果有就关」这种条件句**，那是把未查当已查。

**现场单格式（抄卡时照写）**：`原档位：____（1/5/10/关）→ 本轮：关闭 → 结束还原：□`；
另加一行 `W3 起始时刻：__:__:__`（分窗用，W1 的 `lock`/`drain` 行不算进 W3）。
再预填一行会话锚：`采数日：2026-11-06`（**锚 ②，不写 11-05**——协议写作日与采数日不等，正是纪律要锁的那件事）。
再留一行**锚 ① 终验**：`刷后回读 sha256 短码：____________（12 位，照 §3.0-e 回读值抄）`——
**版本串不算这一格**；六件套 ① 与回执段 0 都引用它（回读哈希升格，v12）。

**W1 两列（v10，§2.1-b）**，现场单上直接画这张小表，十行填满：

### 3.0-e 第九行展开：锚 ① 的终验是回读，不是审脚本（v12）

> **现场只照置顶包 `readback.sh` 跑一条命令**（下面两层与理由回家再读）——这一节不占现场第四屏。

**为什么版本串不够**：`0.3.9-pico26.11.18` 是「这一批」的标签，**不是「这一颗」的指纹**。
同串不同哈希在本仓已有两个实证先例：26.11.17 **双颗**（首落 / 11-05 早重出，`04513f66399d`）、
26.11.18 **返工**（首编 `f9a39db5` 被 `version ok` 拦下 → `5e6f8a89e039`）。
**两颗同串的包，横幅读出来一模一样**——版本串校验对「刷错包」完全盲，假绿就假在这最后一格上。

| 层 | 动作 | 性质 | 能抓什么 |
|---|---|---|---|
| **便宜第一步**（看通道） | 读要跑的那个 `flash.sh`：grep 包路径 / 文件名 / `EXPECTED=` 是否硬编码旧锚 `1f39cc4ce907` | 审脚本 | 旧锚当场现形（`read-pico-github/firmware/flash.sh` 即此例） |
| **必要终验**（产物层） | 刷后 `read-flash` 回读写入区，sha256 对 `5e6f8a89e039` | **回读产物** | 「脚本说刷了 A」是描述，**flash 内容才是端点** |

**即使第一层干净，第二层仍是必要件**——家族规则的严格义：存在性断言的端点是产物本身，不是对它的描述。
现场刷的是置顶包（其 `flash.sh` 已锚 `5e6f8a89e039…`），第一层只花一眼；风险来自「顺手跑了 `firmware/` 里那个」。

**终验参数**（照 `flash.sh` 写入日志的地址）：偏移 **`0x10000`**，长度 **4,216,784 B**（4 B 对齐，整除）：

```sh
python3 -m esptool --chip esp32s3 -p <PORT> read-flash 0x10000 4216784 readback.bin
sha256sum readback.bin   # 应为 5e6f8a89e0398ca4c550b4136d203a261bb924b31823f1716acc1111987e4ffc
```

置顶包内 `readback.sh` 一条命令做完并自动比对（含 esptool v4 `read_flash` / v5 `read-flash` 兼容）；
**一次会话一次**，成本一两分钟。回读值抄进现场单「锚 ① 回读」一行。

**回读哈希升格为锚 ① 的值**：段 0 头部与六件套 ① 回填时**直接引用回读值**（12 位），
① 从「我以为刷的是这颗」变成「**回读验证过的这颗**」。版本串仍核，但只作便宜的旁证，**不作锚**。

| 步 | 做什么 | 产出 | 时长 |
|---|---|---|---|
| 0 | **关自动锁屏、记原档位**（§3.0；结束还原）。**没有第二个定时项要关**（§3.0-c 末句）。**W1 的可执行性依赖这一步**（方案 B 下自动锁与手动锁在日志里分不开） | 现场单一行 | 30 s |
| 1 | 开机，**首屏那一帧**看电量数字与 charging 位 | L3 | 1 min |
| 2 | **插电静置 5 min**，10 s 记一次 `percent / charging` | 观察 B | 5 min |
| 3 | **拔电静置 30 s**（等那一次充电重绘落定） | 干净窗 | 30 s |
| 4 | **W1 定性**：首页「短按 → 锁屏 → 等 2.5 s → 短按唤醒」×10（§3.0-b），记「按下到画面出现」的观感；**同时填两列电量**（锁屏前 / 唤醒首帧，§2.1-b） | 观感 + **两列基线** | 1 min（**+0**） |
| 5 | **W3**：**长按开对话框**（不触摸、设备平放）→ 等 3 s → **3 轮起** × 8 连按，**间隔 < 150 ms、点按不按住**（§2.3-e）→ 不足 10 个合格间隔则**补轮（5 轮封顶）** → 触摸取消。**W3 起始时间戳记在现场单上**（分窗用） | **K3 的 S 项 + 判词 + 基线数** | 4–6 min |

> **第 5 步前的一条硬检查**：最近 **10 s 内无 `lock` / `unlocked` / `drain KEY_*`** 才开始；否则先等干净窗。
> W1 结束时设备是**锁屏态**，第 5 步要先唤醒（唤醒那一下由 20 ms 环吃掉，不产生 take 行，属正常），
> 再长按开对话框。**不要把唤醒那一下算进 W3。**

**顺序不可倒**：按键测试会动屏幕，插电静置要求屏幕不动；拔电静置必须独立一步。

**拔电静置为什么还要保留**（v4 理由换了）：v3 的理由是「W1 的时延样本会被污染」——本轮没有时延样本了。
真正的理由变成两条：① 充电重绘会插进 FIFO，**单 take 事件数会被非按键事件顶高**，正在量的东西被污染；
② `CHARGE_STATE_CHANGED` 边沿会在 W3 中途插一条，让 `id` 跳号判读失真。**30 秒买的是「数得准」，不是「测得准」。**

0. **会话元数据（不占件数）**：锁屏**原档位 → 本轮档位 → 是否还原**（§3.0）；

   这行不写，数据「是不是在锁屏态采的」就无从判断——**它是所有其它结论的前置有效性条件**。
1. **K3 填数：六件套**（v6 定；v7 补血缘与逐行枚举，治的就是「四加一怎么变六」这种对不上的账）——

   | 件 | 内容 |

   **为什么 ⑤ 换了**：v3 的 ④ 是噪声底；本轮 K3 的阈值里**没有人眼成分**，噪声底因此**挪到 ⑥ 管定性**。

   不在这条基线覆盖内**。数照填，但读的人在别的态引用它时，必须知道这是惰性态量的。
2. **K4 措辞已定稿，不再等 severity**：定为「**已入 FIFO 的事件被正确处理**」。
   理由从「severity 可能是 INFO」升级为「**本仓可验范围本来就只有已入队事件**」——
   深度 8 与溢出在 PMU 侧，宿主桩测不到、真机压不满（§2.3）。
3. **W3 记录形态**：逐轮记**各 take 的事件数分布**（如 `2/3/1`）+ 最大单 take 数 + 有无 `id` 跳号，

   **不记 `COUNT`**（读法已废，§2.3-c）。溢出若真发生，现场有一条专用证据：
   `0x7F OVERFLOW, lost`（arg0 = 丢失数）——**比数任何计数器都直接**。
4. 结果并入解耦批开批前提——**基线到账才开批**；K3 的 ④ 件（PENDING）**不阻塞开批**，
   因为它不改变 K3 的断言形式，只标注了这个阈值的适用范围（常态）。
5. **W1 两列基线**（v10，§2.1-b；**不占六件套、不进 K3 判据**，单列一件是为了不被忘掉）：
   **十轮两读数**（锁屏前 / 唤醒首帧）+ **逐行形态标注**（`NORM` / `PIN` / `不可读+原因`）+
   **一致性结论**（`十轮全一致` / `第 N 轮不一致 + 归因`）。

### 6.2 `timestamp_ms` 回绕判别（预登记，本轮无载体）

`timestamp_ms` 是 **u32 开机毫秒**，**49.7 天**回绕。会话撞上的概率极低，**撞上则跨回绕差分全废**。

> **判别式**：`Δt` 为负，**或** `Δt` 明显大于实测间隔（取 3 倍）⇒ 判回绕，该组差分作废。

```
Δt = t2 - t1
若 Δt < 0  或  Δt > 3 × 实测间隔  ⇒  回绕，作废该组
```

**为什么写在这里**：J5 的分钟回绕（`int16`，45.5 天）是同族教训，当时对着负数猜了半天才想明白。
**一行判别式，现场就不用猜。** 本轮 `evt_ms` 无载体，所以它是**预登记**——但它零成本，且下次一定用得上。
