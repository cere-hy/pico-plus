## 二、P1-1：为什么第二信源只能「主动读」

「卡没了」此前只有一条信源：CD 脚，**无去抖、单次采样**。26.9.31 现场 present 在
888/892/923/927 行之间来回跳，就是单信源在抖。CD 擅长「快」，答不了「准」——卡还在槽里、
但已经读不出来（触点氧化 / 半拔出 / 卡内部坏）。

原问题清单的建议是「在 `diskio_sdmmc` 层累计超时」。**本工程做不到**：所有读卡都走 FatFs/VFS，
`diskio_sdmmc` 是 IDF vendor 件，不在改动范围。而判据要求的场景恰恰是「**没人读卡的时候拔卡**」
（首页静止、CD 被飞线短接到 present）——被动观察永远等不到第一个 0x107。所以改成主动心跳：

- `poll_media()` 每拍调 `read_pico_sd_watch_io()`，**在 `get_info()` 之前**（同拍落 lost，不多花一拍）；
- 内部节流：正常态 1 s 读一次 512 B（占空比 ≈0.1%），失败态 100 ms 一次；
- 读固定扇区 0，**不读 FAT/数据区**——心跳问的是「卡还答不答」，不是「文件系统还对不对」。

### 判据：两处参数**不同源**

| 量 | 值 | 角色 |
|---|---|---|
| `SD_IO_FAIL_LIMIT` | 8 次 | 快路径（8 × 117 ms ≈ 0.94 s 提前收工） |
| `SD_IO_DEAD_MS` | 3,000 ms | **判据**：`now - t0 ≥ 3 s` 无条件成立 |

单次 `read_blocks` 最坏 **2×1,000 ms**（失败后还发 CMD13），8 次 = **16 s**，装不进「3 s 内判 lost」；
实测 117 ms 才装得进。写成一个数，下次调采样率就互相打架。

### 三个边界决定

1. **只数 0x107**：`INVALID_STATE`/`NO_MEM` 说明「这次没读成」，不说明「卡不答」。一并计入，
   一次内存紧张就能把好卡判死、卷被无谓卸载。
2. **不改 `present`**：判死只置 `media_invalidated` + `mounted=0`。CD 说在是它的事实，I/O 说卷
   不可用是另一个事实——两个都留，才是完整现场。
3. **换卡清零**：`mount_card()` 成功处（`++s_mount_epoch` 同一临界区）清三个状态。不清的话，
   换卡后第一次心跳带着上一张卡的 8 次**立刻判死**——宿主用例当场抓到。

### 宿主四向（各自独立，先红已验）

| 向 | 打掉什么 | 结果 |
|---|---|---|
| a | 2.1 s（未到 3 s）第 8 次判死，`fails==8` | 绿 |

新增 `PICO_BOOTBB_NOTE_SD_IO_DEAD = 11`（critical；`a`=连续失败次数，`b`=首失败到判决的 ms）。
先跑 `check_bootbb_codes.py` → **红：「未登记级别」**，补 `bootbb_codes.txt` 才过。此前四例都是
事后自查，这一例是门禁先说话。

## 三、B42：牙咬到的是一行**真的假收口**

判据：`main/` + `components/`（vendor 除外）里 `*_quiesce(0)` 零命中。上线即红：

```c
// main/app/app_loop.c（插拔边沿）
if (gained || lost) { ui_avatar_invalidate(); (void)book_cover_jobs_quiesce(0); ... }
```

`quiesce` 的语义是「收口」：停生产者、收句柄，超时是失败。传 0 = 宣布收口、一个 tick 都不等，
返回值又被 `(void)` 扔掉。**代码写着「我等了」，实际一次没等**。卡已经拔了，这行真正想要的是
「别再给我上一页的封面」——那是作废，不是收口。

**修法**：新增 `book_cover_jobs_discard()`（= `cancel(s_generation)`，明确的「不等」语义），
边沿改调它；真正的收口留在 lost 分支三拍（`push_sink_quiesce(2000)`）。**行为零变化**
（原写法本来就是 cancel + 检查一次），改的是名字与语义的统一。

**牙三检，互为锚**：

| # | 判据 | 防什么 |
|---|---|---|
| B42a | 代码（**去注释**）里 `*_quiesce(0)` 零命中 | 假收口回潮 |
| B42b | `book_cover_jobs_quiesce(` 的非零调用 ≥ 2 仍在 | 「把 API 全删了」也绿 |
| B42c | `poll_media()` 边沿必须调 `discard()` | 修法被抹掉 |

去注释匹配的理由：注释里写 `quiesce(0)` 是在**解释这条牙**。与 §13.27 第三坑不矛盾——盘点工具
靠文本认「资产被引用」，这条牙认的是**调用形状**。

## 四、先红工具的回滚锚点：本轮真丢两次码（必须记）

`run_tier1_first_red.sh` 用 `git checkout -- <file>` 还原注入。Tier 1 那批没出事，只因为
**当时工作区恰好干净**。本轮工作区有大量未提交改动，先红一跑：

1. P1a 结束 → `git checkout -- read_pico_sd.c` → **整个 P1-1 实现回到 HEAD**；
2. B42a 结束 → `git checkout -- app_loop.c` → **接线与 B42 修法一起消失**。

两次都是「工具按设计工作，但设计的锚点错了」。修法：注入前 `cp` 到临时目录，还原用副本。
**回滚锚点必须是「改之前的内容」，不是「版本库里的那一版」**——后者只在「工作区干净」这个
非前提成立时才等价。新脚本 `run_p11_first_red.sh` 从一开始就用快照锚点。
