## 三、实现：三条不变量

| # | 不变量 | 代码落点 |
|---|---|---|
| ① | 锚点是**字节偏移**，不是页号 | `book_enter_offline()`：`anchor = reader_page_offset(s_page)` → 重排 → `book_layout_page_for_offset(anchor)` |
| ② | 页脚文案位固定，不被章节名挤掉 | `reader_footer_band_paint()` 掉盘分支：左端恒为 `TF 卡已移除 [· 待落盘 N]` |
| ③ | 任何读卡动作一律**拒绝并出声** | `load_chapter_at()` 单一闸 + `turn_page()` 章末分支 |

**入口结构**：`book_on_media_lost()` 分两个出口——
出口 A：`s_view == READING && s_text && s_text_len` → `book_enter_offline()`；
出口 B：其余情况 / 重排失败 → 原有清场（`free_book` + 回书架）。
**出口 B 是 B′ 唯一允许跳书架的地方，且跳之前必须打 `ESP_LOGE`**（内存不足时）。

**关句柄的顺序**：`book_enter_offline()` 内先 `book_close()`，然后 `app_loop` 才
`read_pico_sd_remount()` 卸载卷——与既有硬顺序一致，不新增时序假设。

**字体**：拔卡瞬间卡上字面已不可读，所以内部先 `ttf_font_open_builtin()` 再重排；
`app_loop` 回调返回后那句同样调用变成 no-op（幂等）。插回卡由 `book_leave_offline()`
调 `app_font_activate_reading()` 恢复用户自己的选择——**不偷偷改他的设置**。

**插回恢复**：`book_on_media_ready()` → 若掉盘态，按 `s_chapter` + 当前页字节偏移重新
`load_chapter()`，落在**掉盘期间读到的位置**，不是拔卡前的旧页。

## 四、B′ 四条件逐条对位

| 条件 | 落法 | 证据形态 |
|---|---|---|
| 1 重排锚点是字节偏移，不依赖封面/prep | `reader_page_offset()` → 重排 → `book_layout_page_for_offset()` | **宿主牙**（`book_layout_host_test` 新增锚点往返段，见第七节） |
| 2 页脚文案位固定、摘抄计数诚实递增 | 掉盘分支固定左端；`N = excerpt_store_pending()`（唯一真值，入队与挂载无关，掉盘照样入队） | 静态牙 B54 + 代码路径 |
| 3 翻到末尾给「存储卡已移除」，不静默 | `turn_page()` 掉盘分支 + `load_chapter_at()` 闸（TOC/书签/跳转同一条路） | 静态牙 B54 |
| 4 当前页文本与位图留 RAM | 文本 `s_text` 不释放（出口 A 不调 `free_book`）；位图 `s_page_images` 冻结，重排后 `reader_offline_rebind_images()` 重绑页号与布局代次 | 静态牙 B54 + 代码路径 |

**tick 重绘清单（四类，逐项）**：

| # | 面 | 谁画 |
|---|---|---|
| ① | 当前页正文（重排后） | `app_loop` 的 `media_event` 分支 `app_present(APP_REDRAW_FULL)` |
| ② | 页脚状态位（`TF 卡已移除 · 待落盘 N`） | 同上（全刷，同一帧） |
| ③ | 摘抄/书签角标 | 同上 |
| ④ | 进度条与页码（按重排后页数） | 同上 |

四类**不是四次局部重绘，是一次全刷**——`poll_media()` 返回 true 后主循环立即
`app_present(APP_REDRAW_FULL)` 并 `continue`（`app_loop.c:1130`）。逐项打勾的意思因此是
「这四类都在那一帧里」，而不是「各有一个刷新调用」。

## 六、内存账（bss 与 PSRAM 分行，不混记）

**bss（`readelf -S` 段读数）**：`.dram0.bss` `0x21550` → `0x21560` = **+16 B**

| 符号 | 大小 |
|---|---|

（`s_page_images`，`prepare_inline_image()` 原本就按页解码到 PSRAM）；本批只做了
「掉盘时不再释放、重排后重绑」。

**交互项**：`.flash.text` 与 `.flash.rodata` 随代码增长，bin 4,132,176 → 4,133,792（+1,616 B）。
bss 账与 bin 大小是两笔账，不互相解释（§13.5 第三课）。

## 九、门禁撞出的第三件事（必须单独说）

第一次全量门禁在 **10/11** 红了，两次报错都**指错了地方**：

| 报错 | 表象 | 真因 |
|---|---|---|
| `reader_fullscreen_host_test.py`：`s_media_offline undeclared` | 抽取式 harness 前奏缺桩 | 真的（第一层） |
| 补桩后 `ui_refresh_feedback_host_test.py`：`s_px undeclared` | 看着像另一个缺桩 | **假的**——`s_px` 前奏里有声明 |

第二层的真因：我在 `turn_page()` 的英文注释里写了 `B' condition 3`（**ASCII 撇号**）。
抽取式 harness 的括号扫描**只跳字符串、不跳注释**，撇号把它带进「字符串模式」，
`{` `}` 计数全乱，抽取范围从 `turn_page()` 越界吞进后面的 `resize_text()`——
后者才引用 `s_px`。**报错位置与故障位置相隔两个函数。**

**处置**：①两处 harness 前奏补桩；②四处注释的 `B'` 改全角 prime `′`。
**对照证据**：注释改完重建，bin 仍是 `6b8f77f3fb97` / 4,133,792 B——注释不进产物，
哈希不变，说明这次改动纯属注释与测试设施，产品行为零变化。

**入册两条**（基线 §13.15）：
1. §13.4 的三处清单升为**四处**——产品构建 / runner gcc 行 / 桩目录符号面 /
   **抽取式 harness 前奏**；
2. 注释引号纪律：被抽取式 harness 覆盖的函数体内，注释不用 ASCII `'` `"`。
   这类失败的表象永远指向越界吞进来的那个符号——与「哈希骗人」「段值骗人」同族：
   **报错位置 ≠ 故障位置**。
