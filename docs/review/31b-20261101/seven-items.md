## 第 1 条 · P0-2 三拍协议（停用 → 收口 → 复位，quiesce 不许传 0）

`media_users_quiesce(2000)`：covers（`book_cover_jobs_quiesce(2000)`）、prep
（`app_book_prep_stopped()`）、push（`push_sink` 空闲或封送已停）、excerpt（同任务，天然安全）。
任一方 2 s 内不停 → **不卸卷**，保留 `invalidated`，走现有 1 s 补卸载闩锁，最多 3 次。
quiesce 超时留痕（谁没停 / 卡在哪个 IO）进验收。

### 第 1 条新增两处扩句（本日并入，来自 B51/B52 证据任务）

**扩句 A · push 判据要数 BLE 路径持有的 FILE\***
`push_sink` 的「空闲或封送已停」不能只看会话状态机。BLE 任务手里有两类句柄：
`.part` 写句柄（`push_part.c:115` `"ab"` / `:122` `"wb"`，接收期间常开到 `do_commit` 首行
`push_part_close()`）、`do_verify` 读句柄（`push_sink.c:994` `fopen(...,"rb")` → `:1003`，
读的是 **`.part`** 不是 push.txt）。记账方式：push_sink 内部量（`s_part` 指针 + verify 进出
加减），**不新增跨组件状态**。

**扩句 B · quiesce 进行中，会话入口冻结**
ARM 时刻的 adopt `truncate` 是**无句柄**存储操作，句柄计数看不见它；掉卡 quiesce 期间 BLE
照常工作，手机此时推送 → ARM 照样进来 → truncate 照样碰正在卸载的卷（covers 同形第三次）。
**不新增机制**——入口闸本来就要做（push 线下一批），31b 只要求三拍期间它同样生效。

> 判据合取式：会话状态机空闲 **∧** BLE 路径 FILE\* 计数为 0 **∧** quiesce 期间入口冻结

## 第 2 条 · P0-3 阅读器不弹屏（B′ 就地重排，四条件）

裁决 1 已定 B′：允许内置字体接管，**按字节偏移重排当前页**（`reader_page_offset()` → 新页），
保证**不跳章、不跳文本位置**；页脚换成「TF 卡已移除 · 待落盘 N」。本批只钉文案位与
「同一段文字」口径（不写「回到同一页」）。

**B′ 四条件**（含本次并入的第 4 条）：

1. 重排锚点是字节偏移，不依赖封面/prep；
2. 页脚文案位固定，摘抄计数诚实递增；
3. 翻到末尾给「存储卡已移除」，不静默；
4. **当前页文本与位图留 RAM** —— 拔卡后不再能从卡上取数据，所以重排所需的文本与位图
   **必须在 RAM 里有一份**；这一条要带**内存账**（新增静态/PSRAM 量按段记账，不给「约」）。

**tick 重绘清单（本日补，对应检查单第 2 项）**：拔卡进入 B′ 后需要重绘的面必须逐项列出，
不许「其它照旧」——拟四类：①当前页正文（重排后）；②页脚状态位（「TF 卡已移除 · 待落盘 N」）；
③摘抄/书签角标（若本页有）；④进度条与页码（页数按重排后算）。清单随落码逐项打勾。

**内存账的记账方式（送审时的承诺，不给数）**：按 commit 5 §22.6 同款——`readelf` 段表 +
`nm` 差集，申报值与实测值并列，差在填充就在填充上说明。**送审阶段不给「约 N KB」**：
没量的数不写，这是 §13.5 第一课（段值骗人）的直接后果。

## 第 3 条 · E-1 摘抄冲账退避（固定三档）

失败重投的退避收口为**固定三档 50 / 200 / 1000 ms**（单一 `s_next_try_ms`：让行 now+5000、
失败按档递增、成功清 0），配套日志 `flushed after N retries (T ms)`。

- 验收：重投次数 389 → **个位数**；UART 占用 **<0.3 KB/s**（现为 10.3 KB/s = 115200 的 89%）。
- **静态可断言形态（本日补，对应检查单第 3 项）**：三档写成**一张常量表**
  （`static const uint16_t k_backoff_ms[] = {50, 200, 1000};`），重试索引只许在这张表上推进
  ——这样「固定三档」不是注释承诺而是可 grep 的代码事实，本批拟配一条牙咬它
  （出现第四个数字或表被改成运行时计算即红）。单一状态量 `s_next_try_ms` 仍只有一处写。
- **因果闭环条款**：31b 落码后复测「存→拔→插」，若「挂载→发布」回到 178 ms 档 → E-1 因果闭合；
  不回 → 归因未闭，不许记 PASS。

## 第 4 条 · E-2 让行锚点（`s_mount_epoch`）

`Mounted` 早于 `mounted=1` 发布 886 ms 是错误的让行锚点。修法：`push_sink` 侧引入
`s_mount_epoch`，`app_loop` 观测边沿；**禁组件 → app 反向依赖**；单片顺序钉死
`poll_sd` → epoch 观测 → `notify_mounted` → `excerpt_store_tick`，把抢跑窗归零。
