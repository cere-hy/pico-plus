## 一、E-2：让行的锚点从「状态差分」换成「事件」

### 1.1 现场与根因

26.9.31 真机：

```
I (100977) read_pico_sd: Mounted APPSD, capacity=... (space pending) at 100977 ms
I (100994) excerpt: flushed, pending=0                     ← 挂载后 17 ms 就写卡
W (101863) app_loop: sd: err=ESP_OK present=1 mounted=1 ... ← 让行从这里才开始计 5 s
```

中间 **886 ms**，每一次家务片都在无让行状态下冲账。

**根因不是「接在哪个 if 上」**，是锚错了对象：`gained = !*mounted && ready` 是**状态差分**。
拔插快于一次轮询时，app 侧看到的 `*mounted` 全程为 `true`——「一直在」与「刚挂载」在快照上
**同形**，边沿一次都不成立。这类缺陷最难查的地方是：状态位每一拍都是对的，日志上毫无异常。

### 1.2 三处落点

| 层 | 落点 | 为什么在这里，不别处 |
|---|---|---|
| 组件 `read_pico_sd` | `static uint32_t s_mount_epoch` + `read_pico_sd_mount_epoch()`；**只在 `mount_card()` 成功分支 +1** | 放 `publish_info()` 会错：`probe_fill_space_deferred()` 会**再发布一次**，同一张卡算两次挂载，窗口推到 20 s 之后——读起来像「摘抄永远不落盘」 |
| `app_loop.poll_media` | 每拍 `excerpt_store_mount_yield(read_pico_sd_mount_epoch(), now)` | 挂载发现的**最早可知时刻** |
| `app_book.excerpt_footer_tick` **首行** | 同上，紧邻 `excerpt_store_tick()` | 挂载发生在 `sd_probe` 任务里，`poll_media` 最早下一拍才知道；把观测压在写卡前一行，**窗口物理上为 0** |

第三处比 §19.4a 要求的「同一循环片」更强：同一函数、相邻两行，中间没有别的事情可插。
§19.4a 要求「注明边沿同步点落在哪一拍」——本批的答案是**落在写卡前一行**，不是「下一片再说」。

### 1.3 幂等放在被调方，不放在调用点

两处都调，同一代号只开一次窗：

```c
void excerpt_store_mount_yield(uint32_t mount_epoch, uint32_t now_ms) {
    if (mount_epoch == s_mount_epoch_seen) return;   // 幂等：同代号不重开
    s_mount_epoch_seen = mount_epoch;
    s_next_try_ms = now_ms + EXCERPT_MOUNT_YIELD_MS;
    /* 退避梯同步归零 */
}
```

这是把 S26-4 的「只看边沿」纪律**从调用频率下移到状态机**：调用点每拍都调是**必需**的
（否则观测不就位），窗口只开一次是**不变量**（否则每拍把窗口往后推，队列永远等不到能落盘的拍）。
两件事分开守，才不会互相将就。

### 1.4 一处行为变化（有意，且要记账）

**开机就带卡，现在也让行 5 s。**

旧断言是 `excerpt_mount_calls == 0`，理由写着「没有『获得』这个边沿，不打扰（开机队列本来就是空的）」。
但那条理由本身就是**状态差分的副产物**，不是 S26-4 的意图——S26-4 要躲的是**书架扫描**，
而开机那一段恰恰是扫描最密集的时候。代号是事件，开机首挂就是 1，照样开窗；队列此时为空，
代价为零。

宿主用例已按新语义改写，注释里写明「旧行为不是更正确，它是副作用」。

## 二、牙：B35 重写 + B58 新增

### 2.1 B35 换锚（同一条牙，跟着结构变）

| | 旧 | 新 |
|---|---|---|
| 正断言 | `if (gained) excerpt_store_notify_mounted(` | `excerpt_store_mount_yield(read_pico_sd_mount_epoch()` |
| 反证 | `if (ready)` 里调 notify | **`if (gained)` 里再调**（点名 E-2 原始病灶） |

### 2.2 B58 新增（五件事，少一条修复就退回）

① 组件有代号且 **只在 `mount_card()` 成功处 +1**；② 有 getter；③ 幂等 + 消费后记录代号；
④ 家务片观测在写卡**之前且相邻**（两者之间 `;` 计数 ≤ 2）；⑤ 旧入口 `excerpt_store_notify_mounted`
在 `main/` **零残留**；另加 ⑥ `excerpt_store_reset()` 必须清代号（否则开机第一次挂载会被
当成「已消费」，窗口永远不开）。

### 2.3 先红：八向，各自独立报错

| 向 | 变异 | 咬它的牙 |
|---|---|---|
| 1 | 组件代号声明消失 | B58 |
| 2 | 递增点搬进 `publish_info()` | B58 |
| 3 | 去掉幂等 `return` | B58 |
| 4 | 观测搬到写卡**之后** | B58 |
| 5 | 退回 `if (gained)` | B35 |
| 6 | `reset()` 忘记清代号 | B58 |
| 7 | `poll_media` 改回旧 API | B35 |
| 8 | 旧 API 在别处残留（不动 poll） | B58 ⑤ |

第 7 向先被 B35 拦下，⑤ 自己也单独验了一次（第 8 向）——一条牙的多个断言不要指望一次变异
就能各打各的，**分层防御要分层验**。

### 2.4 宿主用例

- `excerpt_store_host_test.case_mount_yield`：新增幂等三段（旧代号被忽略 → 立刻落盘；
  新代号开窗 → 5 s 内不落；窗口期满 → 落）。

  只复刻后者，就看不见调用频率。

## 三、`run_dict_hit` 定性报告（裁定要求：随本批交，真机轮前结案）

### 3.1 红点

```
FAIL book_layout_draw_page: does not call justify_target_px()
book_layout_twin_host_test: FAIL
```

`run_dict_hit_host_tests.sh` 属**门外**（68 gap 之一），这条红挂了多久不可考。

### 3.2 判定：**stale**（测试过期），不是产品缺陷

| # | 证据 |
|---|---|
| 1 | `26.9.12` 起绘制侧统一到 `line_ink_width()`——修的是「反色底与字形 run 右边界不同源，右边少盖半个字」 |
| 2 | `line_ink_width()` **体内就是** `line_is_justified(...) ? justify_target_px(...) : line_width`，同一函数、同一组参数 |
| 3 | 命中侧仍直接调 `justify_target_px()`（它要字距调整 target；非对齐行取 0，与绘制侧取 `line_width` 语义一致） |
| 4 | 除这一条，54 处点击 / 四个场景全过 |

### 3.3 修法：拆两层，不是删断言

```
COMMON_HELPERS  两边都必须调（7 条）
DRAW_ONLY       line_ink_width(        ← 绘制侧入口
HIT_ONLY        justify_target_px(     ← 命中侧入口
INDIRECT        line_ink_width() 体内必须仍调 justify_target_px(
```

如果只把 `justify_target_px(` 从绘制侧要求里删掉，测试会绿，但**等价链断在中间也没人知道**：
把 `line_ink_width()` 内部改成手算 `available`，两个循环体看起来一个字没变，右边界已经各算各的。
`INDIRECT` 那一行专门咬这一层。

四向先红：绘制侧不用 `line_ink_width` / 间接链断 / 命中侧不用 `justify_target_px` /
手抄算术回潮（`line_px / 3`）——各自独立报错。

### 3.4 B′ 牵连（裁定点名的那条）

B′ 的就地重排走 `book_layout` 渲染路径，而这条路径上 draw 与 hit **当前同源** → **不继承**
justify 缺陷。

但要说清一件事：这个「不会」在此前**没有任何守卫**。twin 测试在门外红着，谁也不知道它红的
是过期断言还是真缺陷——**「门外有红」的真正代价不是那条红，是它让所有「这里没问题」的判断
都失去了依据。**

已修绿（`PASS`），接入门禁随 Tier 1 批。

## 四、随批：体检批改**串联短路**

原写法 `bash tools/run_gate_health.sh || rc=1` 会让两个 RC 并列输出（`GATE_HEALTH_RC=1` 与
`GATE_RC=1`），读的人容易只盯后一个。改为就地停：

```bash
if ! bash tools/run_gate_health.sh; then
    echo "GATE_RC=INVALID (health chain is red - not issued...)"
    exit 1
fi
```

**先红验证**：往登记簿塞一个不存在的文件 → `GATE_HEALTH_RC=1`、输出 `GATE_RC=INVALID`、
后续 11 步一个都没跑（日志里 `##########` 只有 5 个，全是体检批自己的）。
