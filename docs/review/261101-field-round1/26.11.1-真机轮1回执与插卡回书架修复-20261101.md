## 二、抓虫定案：不是 UI 重绘，是**书源已经关掉了**

你的直觉（「是不是插卡触发了强行重绘/切屏」）方向对了一半：确实在插卡回调里切了屏，但不是「多画了一帧」，是**重开书失败后走的失败路径**。

### 根因（一行）

`book_leave_offline()` 里少了「重开书源」这一步：

```
掉盘：book_on_media_lost → book_enter_offline()
        └─ book_close()          ← 句柄不能跨卷卸载存活，必须关；同时 s_book.count 清零
插回：book_on_media_ready → book_leave_offline()
        └─ load_chapter(s_chapter, anchor)   ← 书源还是关着的
             └─ book_chapter_load(): if (!s_book.file || i >= s_book.count) → ESP_ERR_INVALID_ARG
                  └─ 失败路径：set_reader_view(SHELF) + s_scan_pending = true
```

失败路径本身是**对的**（加载失败就该退回书架并给出「加载失败」提示），错的是**它根本不该失败**——卡已经挂上了，书就在那儿。

### 真机证据：三次同形

| 时刻 | 场景 | 日志 |
|---|---|---|
| t=139446 | 插回卡 | `err=ESP_OK present=1 mounted=1` → `chapter load failed: ESP_ERR_INVALID_ARG` → `shelf books=18` |
| t=300679 | 插回卡 | 同上 |
| t=473148 | 摘抄后插回卡 | 同上 |

**第三次你大概没注意**——因为摘抄照样冲账成功了（478 s 那三行），但书已经被关掉、界面回到书架。也就是说这个 bug 在 A 摘抄组里也发生了，只是被「冲账成功」盖住了。**一次插卡一次命中，100% 复现**。

### 修法

`book_leave_offline()` 先 `book_open(s_path)`，再 `load_chapter()`；重开后做两件校验：

- `s_off_chapters` / `s_off_total_bytes` 对不上（换了卡 / 文件被改）→ **锚点作废，回该章开头**，不拿旧偏移去跳一本已经不是那本书的书；
- `s_chapter` 越界 → clamp 到最后一章。

失败时才回书架，并且给一句「存储卡内容已变化，请重新打开」——**"加载失败" 只留给真的加载失败**。

### 两道牙

| 牙 | 位置 | 咬什么 |
|---|---|---|
| 行为 | `tools/book_source_host_test.c` 新增 4 条 | ① `book_close()` 后 `book_chapter_load()` **必**返回 `ESP_ERR_INVALID_ARG`（真机签名，钉住"不重开就是这个错"）；② 重开后同章可加载；③ 字节偏移语义不变（锚点能落回原处）；④ 换内容后 count/bytes 必变（`same_book` 判据的输入） |
| 结构 | `tools/check_offline_reopen.py`（已接进 11/15） | `book_enter_offline` 必含 `book_close`；`book_leave_offline` 必含 `book_open` **且排在 `load_chapter` 之前**。正反两向实测过：删掉 `book_open` 立刻红 |

**为什么结构牙必须存在**：这个 bug 的特征是「删掉那一句，所有宿主测试仍然全绿」——app 层没有完整 harness（切片 harness 已登记 KF-7.1）。行为牙钉的是**依赖的真实行为**，结构牙钉的是**那一句还在不在、在不在前面**。两者缺一，同样的回退还能再进去一次。
