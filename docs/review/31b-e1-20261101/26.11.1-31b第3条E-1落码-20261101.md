## 三、实现：把「每片都重试」变成「到点才试」

### 3.1 病灶（§19.3 原文）

拔卡后 4.7 s 内 389 次重试、49.4 KB 日志 = 115200 的 89%。**根因不是「重试太多次」，
是失败路径根本不写时间**——每个家务片都无条件再试一次。代码里唯一的时间判据
`s_ready_at_ms` 只管挂载让行，**失败档完全不参与**。

### 3.2 三条改动

| # | 改动 | 代码落点 |
|---|---|---|
| ① | **单一时间判据**：`s_ready_at_ms` → `s_next_try_ms`，让行与退避共用同一个字段 | `excerpt_store.c` 状态区 + tick 首行 |
| ② | **固定三档**：`k_backoff_ms[] = {50u, 200u, 1000u}`，索引封顶末档，**无递增律** | `backoff_on_fail()` |
| ③ | **三条失败路径全接入**：mkdir / open / fsync+close | 三个 `backoff_on_fail()` 调用点 |

```c
static void backoff_on_fail(uint32_t now_ms, const char *what, int err) {
    if (s_retry_count == 0) s_retry_since_ms = now_ms;
    ++s_retry_count;

    const uint8_t step = s_backoff_idx;
    s_next_try_ms = now_ms + k_backoff_ms[step];          // 就是「now + 表值」，无乘除
    if (s_backoff_idx + 1u < (uint8_t)EXCERPT_BACKOFF_STEPS) ++s_backoff_idx;  // 封顶

    const uint8_t bit = (uint8_t)(1u << step);
    if (!(s_logged_mask & bit)) {                          // 每档各一次，只降频不静音
        s_logged_mask = (uint8_t)(s_logged_mask | bit);
        ESP_LOGW(TAG, "%s: errno=%d, keeping %u queued (retry #%u in %u ms, step %u/%u)", ...);
    }
}
```

### 3.3 恢复与重置

- **成功**：`s_next_try_ms = 0`、退避档归零、补一行 `flushed after N retries (T ms)`（仅在 N>0 时）。
- **弃（半行已落盘）**：本条已了结，退避归零、下一条立即可试——卡刚接受过字节，说明它是可写的。
- **挂载**：`notify_mounted()` 写 `now + 5000`，并重置退避档。新一次冲账从 50 ms 起，不继承上一轮末档。

### 3.4 为什么让行与退避必须共用一个字段

两个字段各判各的，就是「让行在挡、退避不在挡」——这正是 389 次风暴的形态：
`tick` 先过让行门（挂载后 5 s 内挡住），5 s 一过，之后每一片都无条件往下走。
**一个门，一条时间线**，B57 用正则把这条钉死：`s_ready_at_ms` 一旦回归即红。

## 四、第 1 条补账：hold 进入必须留痕

**问题**：三拍全败进 `quiesce_hold()` 时只有一行 `ESP_LOGW`。串口日志随会话消失，
下次开机查「push 为什么死了」**零依据**。「失败而不留痕」同族。

**修法**：新增黑匣子事件，由 hold 自己写（不靠调用方记得写）：

| 项 | 值 |
|---|---|
| 事件码 | `PICO_BOOTBB_NOTE_PUSH_HOLD = 10` |
| `a` | 原因码 `push_hold_why_t`：`PUSH_HOLD_WHY_QUIESCE = 1`（三合取等不到）/ `PUSH_HOLD_WHY_RELEASE = 2`（卸卷失败） |
| `b` | 当时仍未关闭的 FILE\* 数——「卡在哪一拍」的直接读数 |
| 关键级 | 进 `note_is_critical()`：环满时可挤掉普通事件，两条都是「只有重启能出」的强信号 |

API 由 `push_sink_quiesce_hold(const char *why)` 改为 `(const char *why, push_hold_why_t why_code)`。

### 4.1 顺带自捕获：冻结事件码没进名字表

加 `PUSH_HOLD` 时发现 **`PUSH_FREEZE = 9`（第 1 条加的）根本没进 `note_name()`**——
黑匣子重放时它打成 `?`，等于「留痕了但读不出来」。同族缺陷，本轮一并补：

```
case PICO_BOOTBB_NOTE_PUSH_FREEZE: return "push-freeze";
case PICO_BOOTBB_NOTE_PUSH_HOLD:   return "push-hold";
```

**这条已升格为门禁体检批第 ④ 项**（事件码三元自检：枚举 / `note_name()` / `note_is_critical()`），
见基线 §13.21。这是执行侧自查抓到的，属正向闭环。

## 五、牙与先红

### 5.1 结构牙 B57（`check_excerpt.py`）

五个断言面：表逐值 `{50,200,1000}` / 封顶 / 单一判据（`s_ready_at_ms` 须消失）/
三条失败路径计数 ≥3 / 验收行。

**七向先红，每条独立消息、互不代劳**：

| 向 | 注入 | 红在哪 |
|---|---|---|
| 1 | 末档 1000 → 800（4× 递进回潮） | `k_backoff_ms[] is ['50','200','800']` |
| 2 | `s_ready_at_ms` 回归 | `the yield window and the retry backoff would be judged by two separate fields` |
| 3 | 删掉 mkdir 那条 `backoff_on_fail` | `appears 3 time(s): expected one definition plus three call sites` |
| 4 | 去掉封顶（无条件 `++`） | `incremented without the clamp` |
| 5 | 验收行文案改掉 | `the acceptance line ... is gone` |
| 6 | 设置点用 `if (0)` 包住 | `wrapped in a never-true branch` |
| 7 | 档数 3 → 4 | `EXCERPT_BACKOFF_STEPS is not 3 in the header` |

### 5.2 宿主用例（`excerpt_store_host_test.c` 新增 `case_backoff_ladder`）

五段，各咬一件事：三档实测间隔（到点才许过，早 1 ms 不许）/ 封顶（第 4、5 次仍 1000 ms）/
留痕计数（六次失败三档 → 恰好三行）/ 让行与退避共用一门 / 挂载重置退避档。

**三向变异隔离，每刀只归因一条断言**：

| 变异 | 红点 |
|---|---|
| 末档 1000→4000 | `tick(2250) == FAILED`（档值直接错） |
| 彻底去封顶 | ASAN `global-buffer-overflow`（越界读表） |
| 失败不设 `s_next_try_ms` | `tick(0) == YIELD`（每片重试，E-1 原状） |

> 补记一笔：最初写的「advance-then-clamp」变异是**等价变异**（先加后夹 == 先夹后加），
> 绿是正常的、不是漏牙。改成彻底去封顶才真正越界。等价变异与漏牙必须分清。

### 5.3 变异靶点

| 靶点 | 变化 |
|---|---|
| M107 | 匹配串从 `s_ready_at_ms` 改到 `s_next_try_ms`；描述里写明**两个后果**（让行失效 + 每片重试） |
| **M107b（新）** | 专切「失败记下次时刻」那一行 → 389 次风暴逐字复刻 |

变异总数改为**动态计数**（`grep -cE '^mutate "'`）。原因：加了 M107b 却忘改硬编码的 17，
日志里出现 `18/17 killed` 这种自相矛盾的绿——**计数与靶点表必须同源**。

### 5.4 先红暴露的弱牙边界

B56 的 hold 留痕断言最初用 `len(re.findall("PUSH_HOLD_WHY_\w+")) >= 2`。
把两处调用**都改成同一个码**时，总数仍是 2 → **牙绿了**。

这是弱牙三型里「`count >= 2` 防单岔」的边界：它防得住「只接一条」，防不住「两条接到同一个码上」。
改为**按每个值分别断言**后，第三向变红。边界已写进基线 §13.21a，列为第四型候选。

## 七、三处未覆盖：挂账 B52，深睡单独归类

裁定原文「只点 lost」，执行按边界走。三处触发点与 lost **共用同一 quiesce 机制**，
属「接线」不属「新机制」，一次接全：

| 触发点 | 现状 | 归属 |
|---|---|---|
| 格式化 | 未 quiesce | B52 / 合流批次 |
| USB 挂载 | 未 quiesce | B52 / 合流批次 |
| **深睡** | 未 quiesce | **B52 单独归类** |

**深睡为什么单独列**：它是**会话中断**问题（BLE 栈先死，句柄不是被抽走的），
失败形态与「卷被抽走」不同——用同一套阈值和超时会误判。B52 设计时分开写，不三处一锅烩。

**交付说明照此写明三处已知缺口**，不写「已覆盖」。真机验证零条也如实记账（§13.16 同族）。

## 十一、门禁

`run_26930_gates.sh` → **GATE_RC=0**（11 步全过，摘抄变异 18/18）。

本轮唯一的**门禁自伤**：M107 靶点因 `s_ready_at_ms` 改名而 MISSED，`TARGET MISSING` 直接让第 3 步红。
