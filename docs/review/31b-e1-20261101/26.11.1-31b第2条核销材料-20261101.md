## 一、内存账：readelf / nm 实数

### 1.1 四个符号的实测大小（可复现）

```
$ xtensa-esp-elf-nm -S --size-sort build_261101_e1/Read_Pico.elf \
    | grep -E "s_media_offline|s_off_chapters|s_off_total_bytes|s_off_chapter_offset"

3fcadce8 00000001 b s_media_offline
3fcadcdc 00000004 b s_off_chapter_offset
3fcadce4 00000004 b s_off_chapters
3fcadce0 00000004 b s_off_total_bytes
```

| 符号 | 类型 | 大小 | 地址 |
|---|---|---|---|
| `s_media_offline` | b（bss） | **1 B** | `0x3fcadce8` |
| `s_off_chapters` | b | **4 B** | `0x3fcadce4` |
| `s_off_total_bytes` | b | **4 B** | `0x3fcadce0` |
| `s_off_chapter_offset` | b | **4 B** | `0x3fcadcdc` |
| **合计** | | **13 B** | |

**地址跨度自洽**：`0x3fcadcdc` → `0x3fcadce8 + 1` = `0x3fcadce9`，跨度 **14 B**；
按 8 字节对齐收口到 **16 B**。这就是「13 B 数据 + 3 B 填充 = 16 B」的实物依据，
不是推算。

## 二、重绘清单：四类面，逐项打勾

| # | 面 | 谁画 | 勾 |
|---|---|---|---|
| ① | 当前页正文（重排后版面） | `app_present(APP_REDRAW_FULL)` | ☑ |
| ② | 页脚状态位 `TF 卡已移除 [· 待落盘 N]` | 同一帧（`reader_footer_band_paint` 掉盘分支） | ☑ |
| ③ | 摘抄/书签角标 | 同一帧 | ☑ |
| ④ | 进度条与页码（按重排后页数） | 同一帧 | ☑ |

**「一次全刷」的代码依据**（`main/app/app_loop.c:1183-1207`）：

```c
bool media_event = poll_media(&ctx, current, &media_mounted, &media_invalidated);
if (!media_mounted) font_retry_settled = false;
if (media_event) {
    ...
    if (menu_open) present_menu(&ctx, current, menu_leaf, &feedback);
    else app_present(&ctx, current, APP_REDRAW_FULL);   // ← 四类面都在这一帧
    vTaskDelay(pdMS_TO_TICKS(LOOP_TICK_MS));
    continue;                                            // ← 旧输入不再触发动作
}
```

**逐项打勾的正确读法**：不是「有四个刷新调用」，是「这四类都在那一帧里，没有第五次局部刷新
给它们擦掉」。全刷之后 `continue`，本轮旧触摸不再派发——否则掉盘瞬间的残留按下会落到新版面上。

### 2.1 边界（如实列，不算覆盖）

**菜单开着时拔卡走 `present_menu()`，不走全刷。** 此时①②③④中的①②不在屏上，
画的是菜单页；菜单关闭后回到阅读器才会画出掉盘版面。

这是既有结构（`menu_open` 分支先于全刷存在），第 2 条未改它，也未验证过「菜单开着拔卡」
这条路径的观感。**列入真机轮观察项**，不当成已覆盖。

## 四、未验（诚实清单）

1. **真机全流程未跑**：四个条件都是宿主 + 静态证据，没有一条来自真机。
2. **菜单开着拔卡**未验（见 2.1）。
3. **重排耗时未测**：内置字面比卡上字面小，重排是同步的，掉盘瞬间那次重排会不会卡帧没量过。
4. **`reader_offline_rebind_images()` 的页号重绑**只有静态断言（函数存在 + 被调用），
   没有「重排后第 N 页的位图确实是第 N 页」的行为用例。
