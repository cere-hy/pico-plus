## 三、为什么不能「先按通过记账」

这与基线 §13.12「没跑 ≠ 绿了」是同族错的另一面：

> **没收到 ≠ 没发生。**

两者的输出形态一模一样——空白。一个是测试没进总入口（输出里看不出来），
一个是日志没进来（输出里也看不出来），而两者的正确处置都是**不记账**。
若拿「用户说测过了」去填位，就等于把推断写进台账，正是家族第 7 例（推断当事实）。

**入册（基线 §13.17）**：任何送审材料的**第一道检查是字节数**，不是内容。
字节数为 0 即判「未达」，不进判读环节；且必须区分「空体」与「无内容」——
前者是通道/生成端故障，后者是结论。判读端不许把前者读成后者。

**这是第二次「材料实体到达但内容为空」**：第一次是 31b 送审 zip 在审计侧解出为空
（后来改成单文件纯文本解决）。两次的共性不是某个人粗心，而是**附件通道没有空体校验**。
处置办法统一为：送审材料优先纯文本直贴或单文件，并在送件时自报字节数。

必须在 `do_verify` 进出各加减一次计数，quiesce 才有东西可判。

| 判据 | 实现要点 | 能红的形态（已验） |

1. **缺证据 ≠ 通过**。任一判据没有观测点，总判定落 `UNAVAILABLE`，不落 `PASS`（§13.12）。
