## 二、条件②逼出的真问题：**闩锁块的位置**（本批最有价值的一行）

31b 的闩锁块在 `poll_media()` 最前面，`s_release_pending` 为真就 `return false`；
而 `gained` 判定在它**后面**。条件②要求「挂载边沿解冻时清 pending」——但那个边沿根本进不去。

```
旧顺序：闩锁（return false）  →  ⋯  → 判定 gained（永远到不了）
后果：  用户插回的卡挂载成功 → 闩锁每拍去卸它 → 掉卡 → 重挂 → 再卸（旧状态污染新会话）
```

**处置：整块下移到 `gained` 处理之后（`app_loop.c:803`）**：

```
判定 ready/lost/gained → gained（清 pending + thaw）→ 闩锁重试（return false）
```

与 §13.36 主裁决（发布顺序）同一族：**顺序不是实现细节，是语义本身**。
本案不是推演出来的——写用例第一跑就暴露（`lost==0`，见 §三坑 2）。

## 三、牙：`remounts_before_quiesce` 采样，不是事后问

新场景（`app_loop` **59 → 60 场景**）：push 的 `FILE*` 永不关 → 跑 16 拍；第 15 拍「关掉」它。

| 窗口 | 断言 | 咬什么 |
|---|---|---|
| 等不到 | `remounts==0 && hold_calls==1 && thaw_calls==0 && quiesce_calls>=5` | 不放弃（没有停在第 3 次）、不动卷、跨档留痕**恰好一次**（bootbb 是 critical 条目，不逐拍刷） |
| 恢复后 | `remounts==1 && thaw_calls>=1 && remounts_before_quiesce==remounts-1` | 卸载走**带闸**路径；成功即解冻 |

最后一条是牙尖：**旧写法放弃闩锁后只能走看门狗，而看门狗路径不过 `quiesce` 闸**。
`quiesce` 被调时记下当时的 `remounts`，能分辨「绕过闸」与「过闸」；事后问 `quiesce_calls`
分不出。同 §13.31「顺序证据只能采样」与 commit 4 的 abort 采样。

**三处坑（全部实测纠正，零入档污染）**：

| # | 坑 | 现象 | 纠正 |
|---|---|---|---|
| 1 | `if (++x == N)` 改写后判据用了自增后值 | 跨档 `hold` 永不触发（`hold_calls==0`） | 先取 `first_slow = (tries == N)` 再自增 |
| 2 | 用例边界没排空函数 static | 上一场景的 `pending`/`mounted` 遗留，新场景首拍进闩锁分支，`lost==0` | 场景开头跑一拍「排空」（quiesce 成功 → remount → pending 清零）再开账 |
| 3 | `uint8_t` 无限自增 | 255 次回绕 → 慢档退回 fast 档 | 饱和 255 |

## 四、TIMEOUT 改动结案（§13.36 修正一的尾巴）

错误推断曾把判死码改成 `TIMEOUT`；实测证明判死码**不决定看门狗入口**（真因在桩）。按批复分两落点：

| 落点 | 现值 | 理由 |
|---|---|---|
| 产品码 `observe_io_dead()` | `ESP_ERR_NOT_FOUND`（`read_pico_sd.c:734`，`return` 在 `:741`） | 26.9.31 立项现场实证的判死签名 `err=NOT_FOUND present=0`（344796 行）。改签名破坏跨版本判读连续性——以后对不上历史签名，判读第一件事得先查「哪个版本改的」 |
| 宿主桩 `get_info()` 判死分支 | `ESP_ERR_INVALID_STATE`（`app_loop_host_test.c:281`） | 镜像真件：`observe_media_locked()` 锁存期把快照重写成 `{present=1, mounted=0, error=INVALID_STATE}`（sd_probe 实测 259）。差一个码，「判死之后还有没有人碰卡」在宿主侧整段没被走到 |

**结论句**：「码是契约，桩是镜像」——契约不许为测试让路，测试替身必须跟着真件走。
§13.12 桩漂移的**第二形态**（与枚举拍平同族）。

## 五、tolerant 可见性：门内假绿的新形态

`test_sd_media_guard` 的案子比「没跑 ≠ 绿了」更深：测试在门禁**内**、输出**绿**、**从未跑过**
——tolerant 按头文件名 `fatal error: esp_timer.h` 吞了它，一次吞掉三个头 + 八个符号。

**运行时规则（本批落地，`run_book_management_tests.sh:30`）**：每次 tolerated skip 打一行
`TOLERATED-SKIP`，带测试名与**实际命中片段**。落地后立刻照出了真相：

```
book_ui:           TOLERATED-SKIP — did NOT pass; matched: book_store_free_snapshot
book_layout_draw:  TOLERATED-SKIP — did NOT pass; matched: line_ink_width
home_recent:       TOLERATED-SKIP — did NOT pass; matched: s_cover_generation
sd_media_guard:    TOLERATED-SKIP — did NOT pass; matched: Assertion `read_pico_sd_get_info(&info)==ESP_ERR_INVALID_STATE …
```

最后一行就是 **B59** 登记的那条过期断言——现在它在门禁输出里**自己说自己没过**，
不再是「绿」。

**§13.32 旁记**：`run_dict_hit` 是**断言过期**（守的东西搬走了）；B59 那条是**断言忠于坏规格**
（「插回也不认卡」把 26.9.29 的死锁当规格守着，绿着的每一天都在证明缺陷还活着）。
处置相同、定性不同：**行为被修正后，固化旧行为的断言必须跟着过堂**。
