### 1.1 段 2 的定位：回归确认，不是首判（**v12 重构；端点已对判据定稿原文**）

**性质先定**：L3 与 B 是**电量批已关账行为的复采**，段 2 是**辅账**（K3 才是主账）。
照此定位，段 2 的**两个面各有各的端点**，不共用一个「有没有载体」的判词：

| 面 | 判据定稿原文（端点） | 输入 | 本轮处置 |
|---|---|---|---|
| **回归面**（本轮主） | 台账 §五 **1671 现象** + **1678 判断**：08:49–08:57 全程 85%（插电）、08:57 拔线 → 91% + 闪电消失 + 画面立刻更新；「**26.11.16 同样**」；26.11.17 真机回执 **1605-1606** 复现正证 | **屏显** `percent / charging` + 时间设计 | **完全可判，照走，不 PENDING** |
| **细分辨率面**（留给未来首判） | 台账 §五 **1683-1690 判据**：原文写明「**下一步，串口，不占设备时长**」，充电中每 10 s 打 `battery_mv / soc_permille / charge_state` 共 5 min，**三支**；分流钥匙是 `soc_permille` 是否跨整数界 | **串口三行** | **载体降级**注记 / PENDING，**不阻塞本轮任何判据** |

**FAIL / PASS 按回归定位写，不按首判写**：
FAIL = **已关账行为复现异常**（冻结不复现、拔线跳变异常、闪电位不消失）；
PASS = 屏显序列与 26.11.16 验收形态一致。
**冻结实锤支（percent 长期不动 + charging 位 + 拔线跳变）在回归面内，照走，不 PENDING。**

**载体预查（上轮已跑，结论保留、分量收窄）**：对出厂 bin `strings` 查
`battery_mv / soc_permille / charge_state` ⇒ **三串零命中**。它**只影响细分辨率面**：
跨整数界的亚整数确认（849→851 屏上未更新 / 界内 851→854）本轮无法落，
记「**载体降级**」注记，解锁条件 = **未来带 battery 打点的 bin**。
**不阻塞本轮任何判据**——段 2 是辅账，别让辅账的载体缺口膨胀成会话级问题。

**纪律 22 双向化回执（推理级判词已对原文）**：用户印象「三支判据原文输入 = 屏显 percent/charging + 时间设计」
被自行标注为**推理级**，要求回填前对判据定稿原文。**本轮已对** `ACCEPTANCE_LEDGER.md` §五：

三支输入确为串口三行**。
⇒ **两面同时成立、各自归位，不是二选一**：回归面按屏显照判（用户的回归定位成立）；
细分辨率面原文依赖 permille，照 **PENDING / 载体降级**归档（用户给的那一支也成立）。
两种账面都诚实，区别只是段 2 里多一条注记还是多一条 PENDING——**都不进段 5 判词**。

### 1.2 段 3 的形态列取值（**统一口径，v11**）

| 取值 | 含义 |
|---|---|
| `NORM` | 无密码形态，唤醒首帧即主页面（旧稿写「无PIN」，**以本骨架为准**） |
| `PIN` | 有密码形态，取数点 = 解锁后首个含状态栏的主页面帧 |
