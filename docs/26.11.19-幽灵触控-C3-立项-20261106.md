## 四、候选机制对比（**全部推理级**，给出判别式）

| 机制 | 与「退一进一」的相容性 | 依据缺口 |
|---|---|---|
| A. 积压重放 | 相容（积压 N 个 tap 逐个消费） | 触摸通道无积压结构（§五 2，已证）；PMU FIFO 不装触摸（已证）——**需先找到「积压发生在哪」** |
| B. 持续鬼点源（静电 / 充电噪声，插线态高发） | 高度相容 | **出事时是否插线 = §二待回填格**，未填之前起点权重不预设 |
| C. 状态残留（按下状态未清，回首页即重触发） | 相容 | 退书路径的按下状态清理需读码（`s_pressed` / `s_press_pending` / `cancel_gesture`，§五 4） |

### 判别式（下次发生时当场可采，写进回执「非预期行为」节）

1. **退出后到再进的时间间隔模式**：大致固定周期 → 噪声节奏（B）；固定短延迟（回首页立刻）→ 状态残留（C）；
   间隔递增 / 一次性连发后停止 → 队列消耗（A）。
2. **换页面后鬼点是否还来**：只在首页且只在继续阅读卡位置 → 热区相关；随机位置 → 源无关页面。
3. **一条读码约束（盘点产出，非结论）**：TAP 需要一次完整 **press→release 边沿**（`ui_gesture.c:53/64`）。
   持续按住不产生 TAP ⇒ 若 B 成立，噪声须是**间歇 down/up 报点**而非常按。这条只收窄形态，不定机制。

> B 假说也标**推理级**。唯一可立即执行的验证：**插线 + 首页静置观测**——本就在 B 组流程里，顺手兼作鬼点观测窗（见真机卡）。

> **〔19:22 校准，原句留痕不删〕** 现场回填「纯电池、没插线」后，这句的**观测窗主次要反过来**：
